# Веб-виджет, данные клиента для AI, инструменты агента — пояснительная записка

Макеты открываются в браузере напрямую (рядом нужны `support.js`, `assets/`, `_ds/`). Тема (светлая / тёмная) и акцент — через Tweaks или `default` в `data-props`. Визуальный язык взят из кода `apps/internal-ui` и baseline-макетов (`Chatballs Baseline v2`, `Веб-чат · поля и оформление`); новых стандартов не заводилось: ссылки `.link`, меню `app-dropdown`, `ui-switch`, бейджи `ToneBadge`, карточки `portal-settings-card` / `administration-card`, окна `DecisionDialog`.

## 1. Оформление: сброс иконок (W3, W3a)

- **Иконка кнопки:** `[Загрузить]` + ссылка **«Сбросить»** — только если загружена своя; возвращает знак агента.
- **Иконка шапки:** `[Загрузить]` + **«Без иконки»** (видна, пока у шапки есть иконка) + **«Сбросить»** (видна при своей иконке или «без иконки»; возвращает «как у кнопки»).
- **Без иконки:** плитка 44px — подложка `n-9`, пунктир `n-6`, перечёркнутый круг `n-5`; подпись «Без иконки · В шапке только название агента». В предпросмотре — шапка без знака, название от левого края.
- W3 интерактивен (ссылки работают), W3a — три статичных состояния: стандартная · своя · без иконки (шапка). «Без иконки» есть только у шапки.

## 2. Форма перед чатом: HTML в согласии (W2, M1, M3, M4)

- Под полем «Текст согласия» — подсказка: «Можно использовать ссылки, жирный и курсив, подчёркнутый, переносы, абзацы и списки (HTML). Остальная разметка покажется простым текстом.»
- В виджете: ссылка — цвет акцента виджета, 600, без подчёркивания (как `ChatAttachment`); жирный — 600 `#262626`; список — отступ 18px.
- **«Редакция N»:** одна строка — как сейчас, в конце через « · » (M4). Абзацы или список — отдельной строкой под текстом, 11.5px `#8c8c8c` (M1 — форма, M3 — согласие без формы).

## 3. Данные с сайта: что видит AI (W1)

- Колонка **«Доступ AI»** вместо тумблера — компактный селект в ячейке (30px, как «Тип»). Варианты в меню с пояснением второй строкой:
  - **Не видит** — AI не получает поле;
  - **Под маской** — AI знает, что значение есть, и может назвать его клиенту, но само значение не получает;
  - **Видит значение** — AI получает значение как есть.
- У заголовка колонки — значок ⓘ с тем же пояснением.
- Поля типа Email и Телефон: «Видит значение» недоступно, причина в меню — «Почта и телефон передаются AI только под маской»; под селектом подпись «только под маской».
- «Поля контакта» (имя, email, телефон): колонка «Доступ AI» с бейджем «Под маской» + подпись карточки «AI получает их только под маской».

## 4. Интеграции → Внешний сервер (X1–X9)

**Список (X1).** Внешние серверы — в общей таблице интеграций. Строка: плитка (нейтральная), имя-ссылка, «MCP-сервер / HTTP-запрос · хост», колонка «Агент · инструменты» → «6 инструментов», статус (Подключено / Ошибка / Не проверено) с подписью, «Проверить», ⋯. Кнопка «Добавить» открывает меню вида: точка входа диалогов · MCP-сервер · HTTP-запрос.

**Страница сервера** — как страница веб-подключения: шапка (крошки, имя, статус, вид, адрес с копированием), субменю 250px, контент 820px.

**MCP (X2–X5):**
- *Подключение:* включён/выключен, название, описание (необязательно), адрес, заголовки авторизации (секрет после сохранения — «•••• сохранено · Заменить»), «Сохранить», «Проверить соединение», статус проверки.
- *Инструменты:* «Обновить список инструментов», дата обновления; у инструмента — название, имя, описание, бейдж «Только чтение» или «Может изменять данные» + «Подтвердить, что только читает».
- *Подтверждение (X4):* окно-предупреждение: что значит подтверждение, чекбокс «Подтверждаю: инструмент только получает данные», запись в аудит.
- *Состояния (X5):* не загружен · идёт обновление · сервер недоступен · неверная авторизация · адрес запрещён · сервер без инструментов. При ошибке последний известный список показан приглушённым с датой.

**HTTP-запрос (X6–X8):**
- *Инструмент:* название для людей, имя инструмента (моноширинно, правила), описание для AI (что и когда), включён; метод GET/POST, адрес с подсветкой `{подстановки}`, у POST — «Только чтение: запрос ничего не меняет»; заголовки как в MCP.
- *Параметры (X7):* строка — имя · тип · обязательный · где передаётся · источник; под ней — «Описание для AI» во всю ширину. Источник: «AI заполняет сам» или данные клиента (Имя, Email, Телефон, свои поля). Пояснения: значение привязанного параметра подставляет система, AI его не видит; свои поля — только в диалогах из веб-виджета. Пример «Как уйдёт запрос» с подсветкой, кто что подставил.
- *Меню строки (X7a):* открыть · дублировать · переместить · удалить.
- *Параметр подробно (X7b):* панель 520px со всеми свойствами и примером подстановки.
- *Ошибки (X8):* неверное имя, подстановка без параметра, адрес в локальной сети; «Сохранить» недоступна, «Исправьте 3 ошибки».
- Пример: «Статус заказа», `order_number` ← поле «Номер заказа».

**Безопасность (4.4)** — жёлтый блок на обеих страницах: «Данные с сайта может подменить посетитель. Ваш API должен сам проверять, что заказ принадлежит этому клиенту.» + ссылка на справку.

**Страница целиком (X9):** загрузка · не удалось загрузить · сервер не найден.

## 5. Карточка агента: «Инструменты» (G3–G6, G9)

- **Место:** правая колонка, сразу после «Модели» — работа инструментов зависит от модели, а связка «Знания» (что агент знает) / «Инструменты» (что агент может узнать) читается и так.
- Группы по серверу (плитка, имя, вид); у инструмента — название, описание, тумблер.
- Без отметки «Только чтение» — тумблер недоступен + «Может изменять данные — включить нельзя. Подтвердите в настройках сервера…».
- Сервер выключен / с ошибкой — группа приглушена, бейдж и причина + «Открыть сервер» (G3, G4).
- Модель без инструментов (G6) — предупреждение в блоке и подпись под полем «Модель».
- Пусто (G5) — текст + «Подключить внешний сервер». Загрузка и ошибка — G9.

## 6. Проверочный чат: тестовые данные (G7, G8)

- Кнопка «Проверить агента» в шапке карточки → панель 420px справа.
- Сверху раскрывающийся блок «Тестовые данные клиента»: имя, email, телефон + свои поля из «Данных с сайта» с контролами по типу (поле, переключатель, список). Пояснение: значения только для проверки и никуда не сохраняются. «Сбросить тестовые данные».
- В ленте — события вызова инструментов в стиле п. 7.

## 7. Чат сотрудника: вызов инструмента (T)

- Системная плашка в стиле «AI передал диалог…» с иконкой инструмента:
  - «Агент запросил «Статус заказа» · 0,4 с · 17:02»;
  - ошибка — подложка и текст цвета ошибки: «… · ошибка: сервер не ответил».
- **Несколько вызовов в одном ответе — группировка:** одна плашка «Агент запросил 2 инструмента · 1,1 с», раскрывается в список с временем каждого; если есть ошибка — вся плашка цвета ошибки, «1 с ошибкой». Так лента не засоряется, а сбой виден сразу.
- Аргументы и ответ не показываются.

## 8. Настройки установки: локальная сеть (A3–A5)

- Раздел «Платформа» (виден только администратору установки), карточка «Разрешить инструментам агентов обращаться к адресам локальной сети», по умолчанию выключено.
- Предупреждение: агенты **всех организаций установки** смогут обращаться к компьютерам вашей сети. Отдельно: сервисы самой установки недоступны в любом случае.
- Включение — через окно подтверждения (A4); во включённом состоянии — «Включено · имя · когда» (A5).

## Решения, требующие подтверждения

1. POST-запрос без отметки «Только чтение» агенту включить нельзя — по аналогии с MCP.
2. Подтверждение «только читает» пишется в аудит и снимается в меню инструмента.
3. Обязательный параметр, привязанный к своему полю, вне веб-виджета остаётся пустым — агент не вызывает инструмент.
4. Вызовы инструментов в одном ответе группируются в одну плашку.
5. Колонка таблицы интеграций переименована в «Агент · инструменты».
6. Своя иконка в макетах — заглушка «Об»; реальный логотип подставляется загрузкой.
