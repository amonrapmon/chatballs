# Веб-виджет: данные с сайта, форма перед чатом, оформление

Макет: `Веб-чат · поля и оформление.dc.html` (открывается в браузере, рядом нужен `support.js`). Кадры W1–W3, C1 — админка; M1–M2 — виджет у клиента. Кейс — столовая «Обед».

## 0. Общая рамка

- Модалка `features/integrations/IntegrationForm.tsx` для провайдера `WEB` заменяется страницей `/settings/integrations/{id}` с субменю (как настройки портала, `Порталы Baseline` PT4): **Основные · Данные с сайта · Форма перед чатом · Оформление · Удалить подключение**.
- «Основные» = текущее содержимое модалки (название, разрешённые домены, код вставки). Код вставки показывается и в шапке страницы с кнопкой «Копировать».
- Всё новое хранится в `integration.config` (JSON) — отдельные таблицы не нужны, кроме значений полей (см. п. 1.3).

## 1. Свои поля (W1)

### 1.1 Схема в настройках
`config.fields: FieldDef[]`
```ts
type FieldType = "string" | "number" | "boolean" | "datetime" | "enum" | "email" | "phone" | "url";
type FieldDef = {
  key: string;          // ^[a-z][a-z0-9_]{0,39}$, уникален, после создания не редактируется
  label: string;        // до 60 символов
  type: FieldType;
  options?: { value: string; label: string; color?: string }[]; // только для enum
  aiVisible: boolean;   // передавать ли значение в контекст AI-агента
  order: number;
};
```
- Лимит — 30 полей на подключение.
- Встроенные ключи `name`, `email`, `phone` зарезервированы: не создаются как свои, пишутся в контакт (п. 1.3).
- UI: таблица «Поля контакта» (только чтение) + таблица «Свои поля» (drag-сортировка, тип — select, для enum — чипы значений `label · value` и «+ значение», тумблер «Видит AI», меню ⋯: переименовать / удалить).
- Удаление поля не удаляет исторические значения, но перестаёт их показывать.

### 1.2 JS API на сайте
В `chat-widget.js` (лоадер) — глобальный объект с очередью, чтобы вызов работал до загрузки скрипта:
```js
window.Chatballs = window.Chatballs || { q: [], setFields(f){ this.q.push(["setFields", f]); } };
Chatballs.setFields({ name, email, user_id, has_active_order: true, order_status: "cooking", order_number: "10482" });
// позже, в любой момент:
Chatballs.setFields({ order_status: "on_the_way" });
```
- Частичное обновление (merge по ключам). `null` — очистить значение.
- Лоадер пробрасывает поля в iframe через `postMessage({ type: "chatballs-set-fields", fields })`; iframe отправляет на сервер: `POST /api/v1/webchat/fields/` (с токеном сессии), до старта сессии — держит в памяти и отправляет вместе со `startSession`.
- Дебаунс 500 мс, склейка нескольких вызовов.

### 1.3 Сервер
- Валидация по схеме: неизвестные ключи отбрасываются, значения неверного типа — отбрасываются с warning в лог (не ошибка для сайта). enum — только `value` из `options`. Строки — до 500 символов.
- `name/email/phone` → поля контакта (только если в контакте пусто или значение пришло этим же подключением — не затираем ручные правки оператора).
- Остальное → `contact_field_values (contact_id, integration_id, key, value jsonb, updated_at)`; хранится последнее значение.
- При изменении значения в открытом диалоге:
  - системное событие в ленте диалога: «Сайт обновил данные: <label> «old» → «new»» (только для полей с `aiVisible` или enum/boolean — чтобы не спамить; правило обсудить);
  - событие по websocket оператору (`useConversationEvents`) — карточка обновляется без перезагрузки.
- Поля с `aiVisible: true` добавляются в системный промпт агента блоком «Данные клиента с сайта» (label: value, для enum — label).
- Безопасность: данные приходят из браузера и **не доверенные** — в UI подписываем «с сайта», не используем для авторизации. (Подписанный JWT — возможное развитие, в этот объём не входит.)

## 2. Отображение в чате (C1)

- `features/conversations` → контекст-панель, вкладка «Контакт»: новая секция **«Данные с сайта»** между карточкой контакта и блоком «Диалог» (через `ContextSection`).
- Строки: label (12px, `--c-n4`) слева 118px, значение справа. Рендер по типу:
  - boolean — бейдж «Да» (ok) / «Нет» (нейтральный);
  - enum — бейдж с цветом из `options.color`;
  - string/number — текст; ID/номера — моноширинно + «копировать»;
  - email/phone/url — ссылка + «копировать»; datetime — локальный формат.
- Недавно изменённое (< 10 мин) — подсветка строки `--c-accent-bg` и время изменения справа.
- В шапке секции — замок + «обновлено в HH:MM». **Только чтение**, редактирования нет.
- Секции нет, если у контакта нет значений.
- Желательно то же в карточке раздела «Контакты» (K3, правая колонка) — вторым этапом.

## 3. Форма перед чатом (W2, M1)

`config.preChat`
```ts
{ enabled: boolean; title: string;
  fields: { key: "name" | "email" | "phone" | string; required: boolean }[] } // string — ключ своего поля
```
- Админка: включатель, список с чекбоксами Имя / Email / Телефон + «Своё поле из „Данных с сайта“», тумблер «Обязательное», заголовок формы, текст согласия (существующие `consentText`/`consentVersion`; при изменении текста версия повышается).
- Виджет (`web-chat/src/ChatView.tsx`): при `enabled` компонент `Consent` + `StartChatFooter` заменяются формой: аватар агента, заголовок, карточка с полями, текст согласия, кнопка «Начать чат» (disabled, пока не заполнены обязательные / невалидны).
- Если значение уже пришло через `setFields` — поле **показывается заполненным** с пометкой «с сайта», клиент может поправить.
- Контролы по типу: email/phone — маска и валидация (телефон — существующий `formatPhone`), boolean — переключатель, enum — select, datetime — нативный input.
- Отправка: данные уходят в `startSession` вместе с принятием согласия; значения формы имеют приоритет над `setFields`.
- Если согласие уже дано и сессия есть — форма не показывается повторно (кроме смены версии согласия).
- i18n: ключи в `web-chat/src/i18n/ru.ts` и `en.ts`.

## 4. Оформление (W3)

`config.appearance`
```ts
{ accent: string;                         // "#RRGGBB"; сейчас уже есть config.accent — используем его
  launcherIcon?: string; headerIcon?: string | null; // URL загруженного файла; null у header = без иконки
  launcherPosition: "left" | "right";     // default right
  launcherSize: 48 | 56 | 64;             // default 56
  launcherShape: "circle" | "rounded" | "square"; // 50% / 30% / 10px
  customCss: string; }
```
- **Цвет**: 8 пресетов (все дают ≥4.5:1 с белым текстом): Синий `#1677ff`, Индиго `#4f46e5`, Бирюза `#0d8a7e`, Зелёный `#15803d`, Терракота `#c2410c`, Малина `#be123c`, Слива `#7e22ce`, Графит `#262626` + поле «Свой HEX». Для своего цвета считаем контраст с белым и показываем предупреждение < 4.5 (сохранять не запрещаем).
- **Иконки**: загрузка SVG/PNG, до 256 КБ, PNG от 96×96. SVG **санитизировать на сервере** (убрать `script`, `on*`, `foreignObject`, внешние ссылки). Хранить в текущем файловом хранилище (диск/S3). По умолчанию — `BotIcon`. Иконка шапки по умолчанию = иконка кнопки.
- **Кнопка**: позиция/размер/форма применяются лоадером `chat-widget.js` (кнопка и iframe живут на странице сайта) — конфиг лоадер получает вместе с `getConfig`. Панель открывается над кнопкой с той же стороны.
- **Свой CSS**: инжектится `<style>` внутри iframe чата (на сайт не влияет). Сервер вырезает `@import`, `url(` с внешними адресами, `expression`. Лимит 10 КБ. Кнопка «Сбросить».
  - ⚠️ Сейчас виджет свёрстан только inline-стилями — нужно добавить **стабильные классы** на ключевые элементы (`cb-header`, `cb-body`, `cb-bubble`, `cb-bubble--client`, `cb-bubble--agent`, `cb-composer`, `cb-start-button`, `cb-form-field` и т.д.) и задокументировать их в справке (ссылка «Классы виджета»). Inline-стили перебивают CSS, поэтому пользовательские правила писать с `!important` или вынести базовые стили в `<style>` с низкой специфичностью — решить при реализации.
- Предпросмотр справа в админке — живой (реальный компонент виджета в режиме preview, если несложно; иначе упрощённая копия как в макете).

## 5. API (сводно)

- `GET/PATCH /api/v1/integrations/{id}/` — расширенный `config` (fields, preChat, appearance).
- `POST /api/v1/integrations/{id}/assets/` — загрузка иконки → `{ url }`.
- `GET /webchat/config` — отдаёт виджету `preChat`, `appearance`, схему полей (без `aiVisible`).
- `POST /webchat/session` — принимает `fields` и данные формы.
- `POST /webchat/fields/` — обновление полей в ходе сессии.
- Contact/conversation API — `siteFields: [{ key, label, type, value, display, color?, updatedAt }]`.

## 6. Критерии приёмки

1. Админ создаёт 4 поля (строка, да/нет, список, строка), сайт вызывает `setFields` — оператор видит значения в карточке.
2. Сайт меняет `order_status` — у оператора без перезагрузки меняется бейдж, появляется событие в ленте, AI в следующем ответе учитывает новый статус.
3. Неизвестный ключ / неверный тип не ломает виджет и не сохраняется.
4. Форма перед чатом: имя и почта пришли с сайта — предзаполнены; без обязательных полей «Начать чат» недоступна.
5. Смена цвета/позиции/формы кнопки применяется на сайте без перевставки кода.
6. SVG со `<script>` после загрузки не содержит скрипта.
7. Свой CSS меняет вид внутри чата и не влияет на страницу сайта.
