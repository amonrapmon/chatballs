# Рабочая доступность в интерфейсе

Выбор собственного статуса реализован в блоке пользователя сайдбара.
Статус и серверное время выводятся в списке сотрудников; поле ответственного
показывает статус рядом с именем. Круглая точка на аватаре отвечает только
за техническое присутствие. В рейке рабочий статус показывается иконкой
и в подсказке аватара.

Источники дизайна в `design/baseline/platform-expansion/`:

- `Чат · состояния.dc.html`: S1–S5 — готовность, сохранение, перерыв онлайн,
  ошибка с повтором и потеря связи.
- `Чат · совмещённые кадры.dc.html`: K2 — меню четырёх статусов с описаниями,
  K1–K2 — ответственный, K6 — рейка.
- `Сотрудники и агенты.dc.html`: E1 — рабочий статус и время отдельно от
  присутствия, фильтр и пояснение внизу таблицы.

Согласованные владельцем дополнения: список управления сотрудниками расширен
полями доступности и фильтром; начальное `UNAVAILABLE / changedAt: null`
показывается без выдуманного времени. В подвале меню тогда остаётся только
пояснение об организации. Супервизор и прочие функции соседних этапов
этой задачей не реализуются.

Сохранённое значение приходит только из REST API текущей организации.
Выбранное значение показывается с «сохраняем…» до ответа. При ошибке остаётся
сохранённый статус, повтор использует тот же ключ операции; конфликт версии
перечитывает актуальную версию и повторяется новой операцией. Ответы с более
старой версией не перезаписывают свежий статус.

Событие `work_status.changed` перечитывает собственный статус и открытые
справочники по действующим правам. После переподключения данные перечитываются;
при открытом соединении опрос идёт раз в минуту, при обрыве — раз в 15 секунд.
Через 3 секунды отсутствия соединения появляется плашка S5, точка собственного
присутствия гаснет. Сохранённый статус не меняется.

## Проверка в штатном окружении задачи

Окружение запускает Skaro. Перед браузером readiness должен подтверждать
database и Redis; `frontend` должен использовать `http://backend-app:8000`.
Вход — существующими документированными демо-учётными данными, без seed,
сброса пароля или изменения прав.

```powershell
docker compose exec -T frontend npm run build
docker compose exec -T frontend npm run test -- src/features/work-status src/features/employees/model.test.ts src/i18n/catalog.test.ts
docker compose exec -T backend-admin python -m pytest chatballs/identity/test_employee_availability.py chatballs/identity/test_employee_list.py chatballs/identity/test_employee_invitation.py --reuse-db -p no:cacheprovider -q
docker compose exec -T backend-admin ruff check chatballs/identity/employee_availability.py chatballs/identity/employee_selectors.py chatballs/identity/employee_support.py chatballs/identity/employee_views.py chatballs/identity/employee_invitations.py chatballs/identity/test_employee_availability.py
```

В браузере сверять каждый выбор с текущим `GET employees/me/work-status/`,
время — с `changedAt`. Проверять отдельно присутствие и неизменность другого
membership. Проверять S2 задержкой настоящего запроса, S4 отключением сети,
S5 обрывом настоящего WebSocket; не подменять ответы API. Во второй вкладке
изменить статус и убедиться, что первая получила событие и обновила подпись
и время без перезагрузки. Затем проверить фильтр списка, ответственного
существующего назначенного диалога и рейку при ширине 1024px.
