# Назначение и рабочие действия супервизора

Форма использует `design/baseline/platform-expansion/Сотрудники и агенты.dc.html`
(E2–E4), рабочий чат — `Чат · совмещённые кадры.dc.html` (K7–K9).
Согласованное исключение в `INTEGRATION.md` сохраняет фиксированную роль
`SUPERVISOR`: её выбирают существующим выбором системной роли, дополнительный
булев признак не вводится. Остальные существующие разделы карточки сохраняются.
Статистика и общая оболочка относятся к отдельным задачам согласно INTEGRATION.md.

Обычное членство (`groupIds`) и область контроля (`supervisedGroupIds`) имеют
отдельные блоки и независимые значения. Флаг API
`permissions.canChangeSupervisedGroups` определяет доступность изменения.
Снятие роли очищает область; пустой набор не расширяет доступ. Сохранение идёт
через существующий API сотрудника, ошибки сохраняют введённые значения.
Аудит показывает переведённые события изменения роли и области без кодов API.

Чат использует эффективные `access.actions`, `canControl`, `canReply` и
`supervised` конкретного диалога. Контроль группы разрешает назначение,
передачу, подключение участников и внутренние комментарии. Он не открывает
публичный ответ, звонок, закрытие, спам или редактирование контакта и меток.
Независимые рабочие права назначенного сотрудника и участника сохраняются.
В дереве щит отмечает только серверную область контроля; текущая область
перечитывается из сессии, независимо от обычного членства.

## Отзыв при открытом диалоге

По согласованию владельца T-064 добавлено поле `supervisionRevoked` в ответ
404 подробной карточки диалога. Оно содержит `groupId`, `groupName`, `actorName`
и `occurredAt` из успешного аудита собственного отзыва области. Запрос ограничен
организацией и самим сотрудником; требуется активное членство и ранее записанная
отметка чтения этого диалога до отзыва. Чужой tenant, аудит коллеги, заблокированное
членство и прямой ID без чтения не возвращают эти сведения. Переписка в 404
не возвращается, схема БД и политика авторизации не меняются.

K8 показывает уже загруженную ленту и карточку, баннер с фактическим инициатором
и временем, скрывает действия и блокирует редактор. Опрос истории, состава,
журнала и состояния посетителя прекращается; загруженный контекст сохраняется;
запоздавший ответ операции не возвращает действия. Строка остаётся на своей
позиции до перехода; затем удаляется. При восстановлении серверного доступа
карточка снова загружается штатно. При самостоятельном праве участия или
назначения сервер продолжает выдавать обычные действия вместо отказа.

Серверный отказ без подтверждённого собственного отзыва использует существующий
экран утраты доступа. Сервер перепроверяет каждую операцию независимо от UI.

Проверки и снимки: [T-064](verification/T-064/README.md).
