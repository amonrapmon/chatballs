# Помощь оператору: серверный API

Маршруты находятся под `/api/v1/organizations/{organization_public_id}/conversations/`.
Нужны действующее членство, видимость, право ответа и открытый диалог. Сотрудник
может отвечать в своём диалоге либо взять доступный неназначенный диалог;
владелец и администратор используют действующие управленческие права.
Запрос помощи сам по себе ничего не перехватывает.

## Запрос и альтернативы

`POST {conversation_id}/reply-assistance/`

```json
{"operationKey": "editor-request-uuid"}
```

Ответ `202`: `suggestion`, содержащий `id`, `attemptId`, `position`, `status`,
`historyVersion`, автора и время. Повтор того же ключа тем же автором возвращает
ту же операцию, включая её конечный результат. Ключи уникальны в организации;
использование ключа для другого диалога, автора или попытки отклоняется.

Альтернатива — тот же маршрут с новым ключом и `attemptId` готовой попытки.
Каждый вариант имеет собственные состояние, версию истории, автора и время.
Первое предложение и предыдущие альтернативы сохраняются без изменения.

## Состояние и решение

`GET {conversation_id}/reply-assistance/` возвращает последние 20 попыток.
`GET {conversation_id}/reply-assistance/{attempt_id}/` возвращает попытку со
всеми вариантами. Состояния: `PENDING`, `RUNNING`, `READY`, `ERROR`.
`originalText` доступен только после успешной обратной подстановки псевдонимов.
`errorCode` — безопасный код; `error` — сообщение из словаря на языке запроса.
Просроченная операция при чтении становится `ERROR/TIMEOUT`, даже если воркер
прервался. Фоновая доставка также проверяет срок.

`POST {conversation_id}/reply-suggestions/{suggestion_id}/reject/` сохраняет
первое отклонение с `rejectedBy` и `rejectedAt`. Повтор сохраняет автора первого
решения. Отправленное предложение отклонять нельзя.

WebSocket рабочего места отправляет `reply_assistance.changed` с
`conversationId` и `attemptId` после фиксации состояния. Текста в событии нет:
получатель перечитывает защищённый API. Перед каждой доставкой сервер заново
проверяет членство, блокировку, активность пользователя и право ответа.

## Ручная отправка

Обычный `POST {conversation_id}/messages/` принимает дополнительные поля:

```json
{
  "text": "Отредактированный сотрудником ответ",
  "suggestionId": "uuid-выбранного-предложения",
  "operationKey": "manual-send-uuid"
}
```

Сервер повторно проверяет права под блокировкой диалога. Исходный AI-текст
сохраняется отдельно; фактическое сообщение, оператор и время связаны неизменной
записью `ReplySuggestionSend`. Защищённая выдача предложения содержит
`sentMessageId`, `sentBy`, `sentAt`. Ссылки из другого диалога или организации,
отклонённые и неготовые предложения отвергаются. Повтор ключа с теми же данными
возвращает прежнее сообщение; другой текст или повторное использование
предложения с новым ключом отклоняются.

Транспорт вызывается после commit сообщения и связи с предложением. Повтор
запроса не повторяет транспортную отправку. Сбой транспорта после commit
не отменяет записанное сообщение и не запускает автоматическую повторную
отправку: это ограничение действующего контура исходящих сообщений.

## Фоновая генерация

В `worker-events` выполняется событие `conversation.reply_assistance_requested`.
Провайдер и модель берутся из агента; включение помощи независимо от автоответов.
Публичная история ограничивается до загрузки текста и включает последнее
сообщение клиента. Реальная версия истории фиксируется при переходе
`PENDING → RUNNING`; затем она неизменна. Инструкции, язык, доступные знания,
статьи и инструменты используют общий контур AI и псевдонимизацию.
Карта токенов существует только в памяти. Повтор события для `RUNNING`
завершает прерванную операцию безопасной ошибкой без второго вызова модели.
Для новой генерации нужен новый ключ запроса.

Генерация не создаёт сообщения, не запускает транспорт, не меняет режим,
ответственного и ожидание ответа. Удаление диалога удаляет его приватную
историю помощи.

## Редактор ответа

Детальная карточка диалога (`GET {conversation_id}/`) содержит
`replyAssistanceEnabled` — включена ли помощь у агента канала. Это подсказка
интерфейсу: право запроса сервер проверяет при каждом обращении.

Интерфейс собран по `design/baseline/platform-expansion/` (кадры A1–A11 файла
«Чат · состояния», K1 совмещённых кадров, компонент «Редактор ответа»):

- кнопка «Черновик AI» в панели инструментов; при выключенной помощи она
  приглушена и объясняет причину подсказкой, в заблокированном редакторе её нет;
- панель над полем ввода показывает ожидание, готовый текст, переключатель
  вариантов, подготовку другой формулировки и ошибку с повтором запроса;
- «Вставить в ответ» заменяет текст поля текстом выбранного варианта и
  закрывает панель; метка у текста отличает нетронутый текст от изменённого;
- «×» на панели черновика отклоняет все ещё не решённые варианты попытки;
  «×» на панели ошибки только закрывает сообщение, готовые варианты остаются;
- отправка — только кнопкой «Отправить» или Enter: текст поля уходит с
  `suggestionId` вставленного варианта и ключом операции. Повтор той же
  отправки использует прежний ключ.

Состояние читается по событию `reply_assistance.changed`; опрос попытки
остаётся страховкой на случай обрыва сокета и просроченных операций.

Ограничения: кнопки остановки генерации нет — сервер не отменяет выполняющуюся
операцию. Панель не восстанавливается при повторном открытии диалога. Ответ с
вложением идёт через маршрут вложений, который ссылку на предложение не
принимает. На экране уже 768px редактор остаётся компактным, без черновика.
