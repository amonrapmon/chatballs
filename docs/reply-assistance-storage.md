# Хранение помощи оператору

## Настройка

Карточка агента в tenant API
`/api/v1/organizations/{organization_public_id}/agents/{channel_id}/`
возвращает `assistanceEnabled`. PATCH принимает только boolean; отсутствие поля
сохраняет действующее значение. Новые и существующие агенты после миграции
получают `false`. Изменение поля не меняет `aiStatus`, настройки модели и
провайдера. Активация и деактивация автоответов не меняют помощь.
Доступ к изменению настройки остаётся через существующее право управления агентом.

## Данные

`ReplyAssistanceAttempt` объединяет исходное предложение и альтернативы,
ссылается на диалог и агента. Её состояние относится к исходной операции,
а не к последней альтернативе. `ReplySuggestion` хранит каждую формулировку
отдельно; `position` начинается с 1 и уникальна внутри попытки.

Обе модели хранят публичный UUID операции, `operation_key`, инициатора как
membership организации, `created_at`, `started_at`, `completed_at`,
`history_version` и состояние `PENDING`, `RUNNING`, `READY` или `ERROR`.
Версия истории — непустой непрозрачный идентификатор ревизии или fingerprint,
предоставляемый вызывающим кодом. Альтернатива сохраняет собственную версию.
Ключ операции уникален внутри организации в каждой модели. Ключ исходного
запроса закрепляется за попыткой; ключ каждой генерации — за вариантом.

При готовности варианта записывается непустой `original_text`. Это исходное
предложение после обратной подстановки персональных значений, а не поле
редактирования оператором. Карта псевдонимов не сохраняется. Для ошибки
предусмотрен только код из `ReplyAssistanceError`, без текста ответа провайдера.

Отклонение готового варианта хранит `rejected_by` (membership) и `rejected_at`.
Оба значения записываются вместе. Новая альтернатива не изменяет исходный
вариант или решение об отклонении.

## Защита и миграции

`ai/0025_reply_assistance` добавляет настройку и таблицы;
`tenancy/0041_reply_assistance_guards` устанавливает FORCE RLS, гранты runtime,
проверки tenant-связей и триггер неизменности источника. Он действует также при
`QuerySet.update`, bulk-операциях и SQL: контекст операции нельзя перепривязать,
готовый текст нельзя перезаписать, завершённую операцию нельзя сбросить для
повторного выполнения, а сохранённое отклонение нельзя отменить перезаписью.
Ограничения БД проверяют сочетание состояния, времени, текста и кода ошибки.

Ссылки защищены от удаления через ORM. Сохранённые попытки входят в штатные
блокирующие связи при удалении карточки агента, включая перенос диалога.
Хранение не создаёт сообщений и событий отправки и не меняет управление
диалогом. Здесь реализованы настройка и данные; вызова AI, фонового обработчика,
API генерации и нового интерфейса в этом изменении нет.
