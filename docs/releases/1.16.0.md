# Chatballs 1.16.0

## Настройка веб-виджета

- Настройки веб-подключения вынесены на отдельную страницу с разделами данных
  сайта, формы перед чатом и оформления.
- Через `Chatballs.setFields` сайт передаёт поля контакта и дополнительные
  данные. Они сохраняются в контакте, отображаются оператору, обновляются
  в диалоге и учитываются в контексте ответа агента.
- Форма перед чатом собирает обязательные поля, проверяет формат и использует
  данные, заранее переданные сайтом. Правки клиента имеют приоритет.
- Настраиваются цвета, положение и оформление кнопки, иконки и собственный CSS.
  Загружаемые SVG проходят очистку. В справке описаны стабильные CSS-классы.

## Установка и обновления

- Обновление из интерфейса сохраняет дополнительные Compose-файлы установки
  в исходном порядке: стандартный override и произвольные файлы через `-f`.
- Помощник обновления получает каталог установки и override-файлы только
  на чтение. Пропавший или некорректный override останавливает обновление
  до перезапуска сервисов. Файлы override не заменяются релизом.
- Для сервера с существующим nginx Chatballs можно разместить на локальном
  HTTP-порту, сохранив стандартный HTTPS-домен снаружи. Пример — в
  `docs/deployment-overrides.ru.md`.
- Dev-окружение задачи использует постоянный каталог PostgreSQL, Redis и media
  вне worktree. Скрипт проверяет исходные секреты и не инициализирует
  отсутствующую базу без явного `-InitializeDatabase`.

## Обновление

Схема базы меняется: `webchat/0006`, `conversations/0027–0028`,
`tenancy/0038–0039`. Штатный сервис `init` применяет миграции при запуске.
Перед обновлением сохраните резервную копию данных и томов секретов.

Если текущая версия ещё не поддерживает override, первый переход на 1.16.0
нужно выполнить вручную: скачать `compose.yaml` релиза и запустить его вместе
с используемыми override-файлами. После этого обновления из интерфейса
сохраняют эту конфигурацию.
