# API рабочей доступности

Все адреса ниже начинаются с `/api/v1/organizations/{organization_public_id}/`.
Организация разрешается из UUID маршрута, доступ требует активной учётной
записи и незаблокированного membership. Статус принадлежит membership.

| Метод и адрес | Назначение и доступ |
| --- | --- |
| `GET employees/me/work-status/` | Собственный текущий статус |
| `POST employees/me/work-status/` | Только собственный переход |
| `GET employees/me/work-status/history/` | Собственная история переходов |
| `GET employees/{user_id}/work-status/` | Собственный статус, OWNER/ADMIN в своей организации либо SUPERVISOR по подконтрольным группам |
| `GET employees/{user_id}/work-status/history/` | Собственная история, OWNER/ADMIN в своей организации либо SUPERVISOR по подконтрольным группам |
| `GET conversations/directory/?q=...` | Существующий справочник получателей, право `conversations.view` |

Супервизор читает статусы и историю коллег только по явно подконтрольным
группам. Обычное членство в группе не даёт этого права; пустая область не
даёт доступа ко всем коллегам. Отзыв области учитывается при следующем запросе.
Управляющие роли могут читать историю заблокированных сотрудников, но менять
чужой статус не могут. Справочник исключает заблокированных и неактивных.

Текущий статус имеет форму:

```json
{"status": "UNAVAILABLE", "version": 0, "changedAt": null}
```

Переход принимает JSON ровно с тремя полями:

```json
{"status": "READY", "expectedVersion": 0, "operationId": "21d454ec-85e4-4368-9d13-5e498c435f6a"}
```

Статусы: `READY`, `BUSY`, `BREAK`, `UNAVAILABLE`. Версия — неотрицательное целое,
идентификатор операции — UUID. Сервер задаёт время; результат содержит
`operationId`, `previousStatus`, `status`, `version`, `changedAt`, `recordedAt`,
`changed`. Повтор UUID возвращает исходный результат даже после новых переходов.
Конфликт версии возвращает HTTP 409; некорректные поля — 400. Повтор текущего
статуса не создаёт переход и не публикует событие. POST чужого статуса отсутствует
(405), поля выбора чужого сотрудника не принимаются.

История исключает операции без перехода и возвращает страницы общего API:
`items`, `page`, `pageSize`, `total`, `pageCount`; порядок — от новых версий к
старым, размер по умолчанию 20, максимум 100. Начальный статус без явного выбора
имеет `changedAt: null` и не создаёт вымышленного рабочего времени.

Каждый сотрудник справочника дополнительно содержит `workStatus` с текущими
`status`, `version`, `changedAt`. Существующие `online`, `lastSeenAt`,
`openDialogs` остаются отдельными признаками. Набор получателей и его поиск не
фильтруются по рабочему статусу.

На существующем сокете `/ws/organizations/{organization_public_id}/conversations/`
после commit фактического перехода приходит
`{"type": "work_status.changed", "userId": 123}`. Это повод перечитать справочник
или собственный статус через REST, а не снимок состояния. Подписка изолирована
организацией; перед доставкой сервер заново проверяет активность получателя,
membership, право справочника и доступность сотрудника в нём. Откат транзакции,
повтор операции и выбор текущего статуса событий не отправляют.

Открытие сокета, ping, потеря сети и закрытие приложения обновляют только
действующее техническое присутствие. Рабочий статус не изменяет ответственного,
видимость диалога и не запускает распределение. Политика обрезки истории при
блокировке относится к будущей интеграции отчётов.
