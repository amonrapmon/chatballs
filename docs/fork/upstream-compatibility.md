# Upstream compatibility map

Снимок интеграции форка с Chatballs 1.19.0. Документ описывает реальные backend-точки и текущие frontend seam'ы ветки test/v119-win11, а не старую структуру из планов.

## Область и статус снимка

- Backend-конфликты были объединены отдельно; шесть frontend-конфликтов теперь разрешены поверх актуальной структуры 1.19.0.
- Старый useConversationHistory.ts был только на стороне форка и удалён. Окна сообщений и внутренних комментариев остаются на upstream features/conversations/useHistoryWindow.ts, вызываемом из useConversationFeed.ts с независимыми курсорами.
- Однозначный счётчик upstream-файлов, изменённых в текущем дереве относительно `v1.19.0`: `git diff v1.19.0 --name-only --diff-filter=M -- apps/backend apps/internal-ui`. Сейчас это 50 существующих изменённых файлов: 37 backend (включая 3 тестовых) и 13 frontend. Добавленные/удалённые/переименованные файлы, форковые приложения, миграции расширений вне этих каталогов и этот документ не считаются.
- 1.19.0 разделил модели и AI-turn на message_models.py, ai_turn_state.py, ai_turn_completion.py, ai_turn_result.py и ai_reply_delivery.py; добавил организационный режим OPERATORS_ONLY, версии режима, назначения и проверки назначенного оператора; расширил историю и добавил внутренние комментарии и почтовые продолжения. Интеграционные проверки обязаны проходить через эти актуальные точки.

**Нерешённый Gateway contract mismatch:** проверенные producers в intercom-gw-fresh/main (tg-gateway/src/destinations/chatballs-destination.ts и max-gateway/src/destinations/chatballs-destination.ts) отправляют schema intercom-gw.chatballs.operator-mirror.v1, occurred_at и message data, но не отправляют origin.provider_event_type. Timestamp может быть null. Chatballs gateway_ingress/native_operator_adapter.py:handle_native_operator_mode требует origin.provider_event_type == outgoingMessageReceived и ненулевой timestamp в ENABLED, поэтому текущие producer events fail closed (409/400). Не ослаблять проверку молча. Нужен выбор владельца контракта: добавить проверяемую provenance attestation в Gateway producer/schema либо утвердить иной доверенный способ её передачи. До этого producer-consumer совместимость в ENABLED не подтверждена.

## Что можно будет вынести из upstream touchpoints

Доменная реализация уже находится в собственных модулях: native_mirror/*, gateway_ingress/*, conversations/gateway_delivery.py / gateway_http.py и crm_bridge/*. Это не устраняет необходимость коротких интеграционных hooks в upstream.

После появления явного upstream extension interface можно убрать из upstream следующие extension-only branches:

- conversations/apps.py — импорт Gateway event handler; перенести регистрацию в app config Gateway.
- conversations/operator_messages.py — проверку Gateway provider и вызов его собственного outbound adapter.
- client_details.py, selectors.py, read_views.py, serializer_context.py, webchat/message_selectors.py — Native Mirror visibility calls за общей точкой message-scope extension.
- message_views.py — Native Mirror removedIds за response/delta hook.
- identity/audit_catalog.py — CRM audit labels за регистрируемым каталогом labels.
- features/conversations/useHistoryWindow.ts — применение `removedIds` из Native Mirror через hook для delta transforms сообщений.
- features/integrations/IntegrationForm.tsx и useIntegrationForm.ts — Gateway fields, validation и payload через регистрацию provider form.
- features/integrations/model.ts и ConnectionsTable.tsx — Gateway provider metadata, настройки и подпись подключения через provider registry/render extension.
- features/settings/SettingsPage.tsx — CRM settings card через organization settings slot; CRM component, API и state уже принадлежат crm-bridge.
- features/sales/dialogs/context/ClientContext.tsx и features/sales/client-detail/SalesClientHeader.tsx — CRM profile links через slots расширения contact/conversation actions; сами ссылки уже принадлежат crm-bridge.
- i18n/en.ts и i18n/ru.ts — CRM locale inclusion через upstream-supported catalogue registration/code generation.

Это кандидаты после появления соответствующих upstream extension points, не готовые extraction points сегодня. AI-turn revision guards в ingest.py, ai_turn_state.py, ai_turn.py, ai_turn_completion.py, ai_reply_delivery.py и ai_turn_result.py должны оставаться синхронными с upstream pipeline и его locks, пока upstream не предоставит hook, который вызывается в тех же транзакционных границах. `conversationApi.ts` остаётся endpoint/schema seam; Message fields, Gateway provider enum, URL/app registration и миграции также остаются shared-schema/bootstrap seams.
