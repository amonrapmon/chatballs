# T-155: проверка прокрутки и диагностика почты

## Изменения

ResizeObserver отслеживает viewport и содержимое ленты. Рост редактора и медиа
удерживает низ, если сотрудник следовал за ним; чтение истории не прерывается.
Допуск у низа сокращён с 200 до 2 px (округление браузера): входящее больше
не прерывает чтение рядом с последним сообщением.
Догрузка рассчитывает позицию от сохранённого scrollTop, без удвоения browser
scroll anchoring и без учёта входящего в высоте старой страницы.
Убран верхний padding редактора (10 px desktop / 8 px mobile). Мобильная
проверка выявила переопределение общим CSS; селектор исправлен. Это разрешённое
задачей отклонение от «Чат · совмещённые кадры.dc.html». Остальной baseline сохранён.
Выбранный ящик сохраняется при обновлении options; его исчезновение блокирует
отправку вместо подмены на первый. Меню позволяет выбрать другой доступный ящик.

По прямому решению владельца отменено требование привязки EMAIL-ящика к агенту
для продолжения WEB-обращения. Решение зафиксировано в
[docs/decisions/T-155-agent-independent-email.md](../../decisions/T-155-agent-independent-email.md).
Доступность, отправка и повтор больше не зависят от канала ящика. Poller
опрашивает активные EMAIL-ящики без привязки; связанные ответы используют
агента и маршрут исходного WEB-диалога. Без активного обычного маршрута
несвязанные письма не создают обращений. Статусы, секреты и данные ящиков
не изменялись для реализации решения, production не перепривязывался.

## Почта

В локальной копии EMAIL №4 info@atelie-nord.ru и №21 support@example.test
относятся к разным организациям; №21 — demoSeed. Штатные HTTP API integrations
и email/options организации 1 первоначально возвращали №4. Его штатная проверка
POST /integrations/4/test/ получила ошибку DNS IMAP и сама установила ERROR;
после этого email/options вернул пустой список. Успех не подставлялся.

По предоставленному владельцем SSH выполнена только диагностика 171.22.130.156.
В БД сервера одно организационное EMAIL-подключение: №19 inbox@edevs.tech,
активно, секрет есть, UNCHECKED, channel_id=None. Причина исключения вычислена
штатным mailbox_available и подтверждена штатным integration_payload:
нет канала агента. Отсутствие OK не причина, проверяется status != ERROR.
Штатный check_email вызван без сохранения: IMAP прошёл, SMTP вернул
«101 Network is unreachable». Сохранённый статус остался UNCHECKED.

Ещё есть SMTP почты установки (smtp.mail.ru:587, тот же адрес). По ADR-0015
это почта приглашений/восстановления, не второе диалоговое подключение.
Прежний контракт ADR-0015 и poller требовали привязки ящика к агенту.
Владелец отменил это требование для почтового продолжения. Изменены и проверка
доступности, и poller; получение связанных ответов также работает без привязки.
Фильтры организации, прав, активности, ошибок подключения и демо сохранены.
Диагностика не обнаружила второго диалогового EMAIL-подключения организации.

Новые девять адресных тестов используют штатные API и реальную тестовую БД:
два непривязанных ящика в options, чужой ящик исключён, выбранный transport
доходит до outbox, источник WEB сохраняется; ответы и их дубли возвращаются
в тот же диалог, закрытое обращение получает штатного WEB-преемника.
Начальная инициализация курсора IMAP больше не ждёт появления треда.
Несвязанные письма, другой отправитель или ящик без активного обычного
маршрута не создают обращений. Существующая обычная EMAIL-маршрутизация
и проверки секретов/хостов/demoSeed/ERROR/активности не потеряны.
Изоляция транспорта в тестах не является запуском mock-сервиса.

На текущем backend через Playwright HTTP: readiness database=true/redis=true,
вход существующей демо-учётной записью успешен, integrations показывает
реальный ERROR №4 с причиной DNS; email/options №31 не предлагает этот ящик.
Статус успеха ради доступности не подставлялся.

## Открытая приёмка

Подтверждены открытие/переключение ленты, все три режима, рост редактора,
чтение при входящем и UI-догрузка. Изменения кода и решение владельца завершены.
Выбор двух пригодных ящиков в браузере и внешняя отправка/связанный ответ
не подтверждены: в копии нет двух реально пригодных почтовых подключений.
Серверный SMTP недоступен; привязка к агенту теперь не требуется и не создавалась.
Это ограничение реальных подключений, а не основание менять их секреты или
подставлять успешный статус. Дополнительных данных владельца для написания
кода не требуется. Два независимых ящика и выбранный transport проверены
адресными тестами штатных API/outbox; это не заявляется внешней SMTP-проверкой.
Production, настройки, секреты, статусы, доступы и сервисы
сервера не изменялись. Нет mock-сервисов, seed, сбросов учётных данных
или отправок посторонним адресатам.
