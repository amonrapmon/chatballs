# Проверка T-093

Проверка выполняется в штатном окружении `skaro-chatballs-t-093`:
frontend `http://localhost:20022`, backend приложения `http://localhost:20020`.
Прокси frontend возвращает HTTP 200 для `/api/v1/health/ready/`,
с подтверждением подключения БД и Redis. Установленный демо-набор проверен
чтением базы; seed, изменение учётных данных и заглушки не использовались.

## Проверенные сценарии

- Администратор создал причину через интерфейс, переименовал её, отключил
  и включил. Повторное название отклонено штатным API с HTTP 400;
  поле ввода и серверная ошибка сохранены. Счётчик использований и
  сведения о переименовании читаются с сервера.
- Все четыре переключателя изменяемы. «Готов» отключён через UI с HTTP 200,
  затем исходная разрешающая политика восстановлена.
- У сотрудника настройки отсутствуют в меню; запросы справочника управления
  и политики возвращают HTTP 403. Доступность действия передачи определяется
  `access.actions`, выбор получателя — `assignmentAllowed`.
- Передача без причины показывает ошибку и не отправляет POST.
  Реальное отключение сети сохраняет форму. Явный повтор использует тот же
  UUID операции. После конкурентного назначения сервер вернул HTTP 409,
  карточка обновилась, отправка заблокировалась; скрытого повтора не было.
- Отключение допуска рабочего статуса исключило даже сотрудника онлайн;
  разрешающая политика допускает сотрудника офлайн. При обновлении списка
  недоступный выбранный получатель сбрасывается с пояснением.
- Елена передала диалог Анне; Анна получила уведомление в другой открытой
  карточке и открыла переданный диалог кнопкой уведомления. Обратная передача
  доставила уведомление Елене. Причина и комментарий появились в защищённой
  карточке и последних передачах; обычное уведомление и системное сообщение
  содержат только безопасный текст и ссылку на запись.
- Ошибок JavaScript (`pageerror`) при этих сценариях не зафиксировано.
- После последнего изменения пояснение администратора проверено в браузере:
  «Ответственным станет Светлана Петрова», без предупреждения о потере прав.
  У сотрудника проверено сохранение полного предупреждения из макета.
  Существующая проверка ролей подтверждает одинаковую ветку OWNER/ADMIN.
  Снимки: [администратор](transfer-admin.png), [сотрудник](transfer-employee.png).

запрашивают серверные фильтры и содержат только соответствующие события.
