# Проверка результата T-113

14.10.2026, изолированное окружение `skaro-chatballs-t-113` на исходниках задачи.
Frontend: `http://localhost:20010`; backend-app: `http://localhost:20008`.
`docker compose ps` подтвердил backend-app, backend-admin, frontend, postgres
и redis. Frontend использует `VITE_DEV_API_TARGET=http://backend-app:8000`.
`/api/v1/health/ready/` через frontend подтвердил database=true, redis=true.

Запуск выполнен инструментом Skaro. В команду добавлен документированный
backend-admin для READ ONLY проверки экспортов. Существующие данные и аккаунты
не пересоздавались, seed и подмены API не использовались.

## Экспорт и окончательная проверка

ST6–ST8 завершены после указания владельца продолжить с предложенными правками.
Меню CSV/XLSX, окно 520 px, порядок параметров, подготовка и ошибка сопоставлены
с исходным HTML. Согласованные исключения: подпись о текущих фильтрах без вкладки,
нет строки «Раздел», CSV использует запятую, подготовка без вымышленного процента,
общая ошибка без несуществующего лимита 92 дня. Снимки: `reports-export-menu.png`,
`reports-export-preparing.png`, `reports-export-error.png`.

CSV и XLSX реально скачаны через кнопки UI в двух вариантах завершённого периода
8–12.10.2026 Europe/Moscow: без дополнительных фильтров и с employee=3, group=2,
transport=MAX, connection=3. В отфильтрованном экране одна строка Анны Ким;
в JSON и файлах тот же сотрудник и те же параметры. Скачивание успешно и окно
закрывается. Экспорт из вкладки нагрузки использует тот же полный базовый отчёт.

`verify_downloads.ps1` передаёт реальные скачанные файлы и JSON в backend-admin,
`verify_downloads.py` сравнивает все пять серверных таблиц: параметры, показатели,
детали обращений, рабочие статусы, детали статусов. Оба варианта прошли. Сравнение
приводит ISO даты к одному UTC моменту (JSON может сериализоваться со смещением
выбранной зоны) и учитывает равенство числовых записей 0/0.0. Игнорируется только
время формирования отдельных запросов; значения, единицы, полнота и детали
не исключаются. В XLSX нет формул. Локальные файлы находятся в игнорируемом
`downloads/`, их можно заново получить штатным UI и проверить:

```powershell
./docs/verification/T-113/verify_downloads.ps1 -Folder ./docs/verification/T-113/downloads/default
./docs/verification/T-113/verify_downloads.ps1 -Folder ./docs/verification/T-113/downloads/filtered
```

Текущий незавершённый период тоже скачан. У его открытых интервалов время
естественно растёт между запросами, поэтому он не заявлен как побайтовое
совпадение разных снимков. Неполнота, «—» и текущая нагрузка 0 в UI сопоставлены
с API. Во вкладке нагрузки отфильтрованная строка имеет currentLoad=0,
waitingReplies=0, недоступный итог статусов «—» — как в штатных источниках.
После последнего запуска Skaro повторно сопоставлены все семь строк нагрузки
и ожидания ответа с JSON отчёта и обеими штатными страницами ленты (обычная и
архивная), ошибок нет. CSV успешно скачан также с вкладки нагрузки; URL содержит
активную организацию и выбранный период, без вымышленного параметра вкладки.

Для ST8 использовано реальное отключение сети browser context: окно сохраняет
формат и все параметры, «Повторить» после восстановления успешно скачивает
файл с прежними границами. Для ST7 реальное замедление сети Chromium показало
«Готовим файл…»; «Отмена» завершила запрос с ERR_ABORTED. За следующие 4.5 секунды
скачиваний не было. Ответы не перехватывались и не подменялись.

## Ограничение существующих данных

ST9/ST10 нельзя достоверно вызвать для полной истории на имеющемся наборе:
API сохраняет признак неполной истории старых обращений. Его ответы не заменялись
и новые данные ради получения этих состояний не создавались.
Условия пустоты проверены адресным тестом: только полная история без событий
переходит к пустому состоянию; неизвестная история и незавершённые интервалы
не подменяются нулём. Разметка этих состояний проверена по исходному baseline;
это не утверждение о вызове ST9/ST10 на реальных данных.

После последних изменений: сборка TypeScript/Vite и адресные проверки i18n,
маршрута/доступа прошли. Предупреждение Vite о существующих больших чанках
не препятствует сборке. Новые модули фичи имеют 8–89 строк; страница 42 строки,
контроллер экспорта 46, окно 30. Смешения модели, HTTP и layout в одном крупном
компоненте нет; исходный HTML baseline не менялся.
Последняя правка касалась только оформления кнопок в окне подготовки: сборка
повторно не запускалась по правилу владельца для мелкого CSS. После неё
окружение повторно запущено Skaro и состояние подготовки проверено в браузере.

При передаче результата Skaro подтвердил все три критерия и обнаружил конфликт
двух каталогов с main `8d364118` (клиентские оценки). Main влита в ветку задачи;
ru/en сохраняют импорты и spread обоих отдельных модулей: отчётов и оценок.
После разрешения конфликтов штатное окружение перезапущено, полная сборка
internal-ui и три теста каталога прошли. Повторная браузерная проверка подтвердила
русский заголовок, меню и успешное штатное скачивание CSV. Проверялись только
сценарии, затронутые разрешением; логика отчётов и оценок не переписывалась.
