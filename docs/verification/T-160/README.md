# Проверка T-160

Штатный контур Skaro `skaro-chatballs-t-160`: frontend http://localhost:20004,
backend http://localhost:20002, platform http://localhost:20003,
web-chat http://localhost:20005. Frontend использует
`VITE_DEV_API_TARGET=http://backend-app:8000`. Readiness: database=true,
redis=true; compose показывает healthy PostgreSQL, Redis и backend-app.
Для целевых pytest через Skaro добавлен предусмотренный проектом backend-admin,
без host-порта. Запуски и пересборки выполнялись только start_environment.

Наличие демо-набора INSTALLED и ADMIN проверено read-only в tenant_atomic.
Вход — существующие учётные записи из штатного демо-манифеста. Seed,
bootstrap, сбросы паролей/прав/томов, подменные ответы API и временные серверы
не применялись. Навыки для проверки созданы продуктовым UI; это обычные
операции в копии данных задачи, не установка набора данных.

## Исполняемые проверки

```powershell
docker compose exec -T frontend npm --workspace @chatballs/internal-ui run build
docker compose exec -T frontend npm --workspace @chatballs/internal-ui run test -- src/features/skills/model.test.ts src/features/skills/presentation.test.tsx src/router.test.ts src/auth/access.test.ts src/api/client.test.ts
docker compose exec -T backend-admin pytest -q --reuse-db chatballs/ai/test_skills_api.py chatballs/ai/test_skills_access.py
ruff check apps/backend/chatballs/ai/skills_views.py apps/backend/chatballs/ai/test_skills_api.py
git diff --check
```

Полный прогон проекта не запускался. Логи: build.txt, frontend-tests.txt,
backend-tests.txt; отдельная повторная проверка счётчика связанных агентов —
filter-tests.txt. Первоначальный запуск npm на хосте выявил отсутствие локальных
node_modules; все засчитанные сборки и проверки выполнены в штатных контейнерах.
Промежуточные ошибки типов и тестов исправлены до финальной проверки.

## Браузер и макет

Playwright MCP задачи. Проверяется само приложение с session/CSRF и штатным
backend. Для сетевых ошибок применялся offline браузерного контекста: API
ничем не заменялся. Конкурентная правка — реальный PUT с другой ревизией.

Исходный HTML baseline просмотрен отдельно как статический дизайн-документ:
в памяти браузера подставлены его неизменные support.js/chat-model.js,
снимки baseline-*.png. Это просмотр макета, не работающая страница приложения.
В продукте эти runtime-файлы не используются. SHA-256 исходных файлов совпали
с исходной копией и утверждённым docs/agent-skills-design.md.

Показанные K/A сохранены в снимках приложения. Данные — фактические названия,
авторы, даты, подключения и шаблоны, полученные от API. Аннотации холста и
«Новый блок» в новую функцию не переносились. В существующих блоках агента
порядок: Инструкции → Навыки → Знания; справа Назначение → Помощь сотрудникам →
Подключения → Модель → Инструменты.

## Структура и граница зависимой задачи

Новая feature разделена на API/модель, hooks локального ввода и запросов,
таблицу, форму, диалоги и карточку агента. SkillEditor — композиция подвидов;
подтверждение ухода, поля, заголовок, шаблоны и боковая колонка отделены.
Существующий AgentsPage разделён на страницу, AgentRow и CreateAgentModal.
Новые компоненты <180 строк, остальные новые модули <300 строк.
Большие существующие i18n ru/en изменены только импортом и включением отдельного
каталога skills, без переноса feature в агрегаторы.

Шаблоны готовой основы перечисляются из реальной configuration.templates.
SkillEditor/SkillsWorkspace принимают TemplateEditorBridge: configuration,
templateId|null, change(configuration), save() и back(). Зависимый редактор
получает тот же локальный набор и ту же атомарную границу сохранения. До его
подключения действия добавления/редактирования недоступны с пояснением;
фиктивного T1 и обходного редактора кода нет. Удаление шаблона локальное и
сохраняется вместе со всем навыком. Полный сценарий T1–T4 остаётся зависимой
задаче skills-template-editor-ui.

## Изменение подключения стилей

В штатном Vite на bind mount Windows запрос src/styles.css зависал при обработке
вложенных @import; сам backend и отдельные CSS-модули отвечали. Агрегаторы
styles.css, employees/styles.css, sales/dialogs/styles.css заменены модулями
импорта styles.ts. Содержимое всех 46 конечных CSS-файлов и порядок подключения
сверены программно и сохранены. Это устранение препятствия штатной проверке,
без изменения оформления остальных разделов. Новые стили навыков также
подключены обычными импортами, разделены по ответственности.

## Итог проверки текущего кода

Сборка завершилась успешно за 1m 21s; предупреждение Vite о размере chunks
не блокирует сборку. Frontend: 5 файлов, 50 passed. Backend: 9 passed,
с `--reuse-db`; предупреждения относятся к существующим CheckConstraint и
каталогу staticfiles. Ruff и git diff --check прошли. Полного прогона не было.
