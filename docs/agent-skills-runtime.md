# Инструкционные навыки в ходе агента

Контракт T-158: ADR-0036, SPEC-0035 R-5–R-10, дополнения SPEC-0008/0023.
Работает для навыков без шаблонов. Шаблоны, их схемы, оформление и UI этой
задачей не добавляются. Помощь сотруднику и анализ качества не подключаются
к навыкам автоматически.

## План и снимок

Живой ход (`conversations.ai_turn`) и существующий POST
`/api/v1/agents/{channelId}/test-chat/` вызывают общие `plan_chat` и
`run_turn_chat`. При планировании один SELECT с JOIN читает явно подключённые
навыки, проверяя организацию навыка, связи и агента. FORCE RLS сохраняется.
Каталог и инструкции копируются в неизменяемые объекты в памяти. После
планирования обращений к библиотеке нет: правка, отключение и удаление,
зафиксированные во время сетевой части, действуют со следующего плана.

В начальный запрос попадает JSON-каталог только с `id` (public UUID), `name`
и `description` (условие применения). Инструкции не входят в начальные
сообщения, описания функций, диагностический снимок или repr плана.
Примеры автоматически не загружаются.

Внутренняя функция `chatballs_load_skill` принимает ровно
`{"skill_id": "<id из каталога>"}`. При совпадении с именем предложенного
HTTP/MCP-инструмента получает первый свободный суффикс `_1`, `_2` и т. д.;
внешние имена и их маршрутизация сохраняются. Модель видит фактическое имя.
Загрузка возвращает только `{"instruction": "..."}` из снимка этого хода.
Неизвестный, чужой и неподключённый ID дают одинаковый `skill_unavailable`.
Некорректный набор аргументов даёт `invalid_arguments`; истёкший срок —
`timeout`; превышение объёма инструкции — `skill_too_large`. Исходный ввод
и чужие данные в ошибки не включаются. Исправление происходит внутри общего
цикла; дополнительного цикла для навыков нет.

Инструкция — сценарное правило организации, подчинённое системным
ограничениям, языку ответа и передаче человеку. Загрузка не подключает
инструменты и не расширяет права. Внешние HTTP/MCP-результаты остаются
недоверенными данными независимо от наличия навыка.

## Совместимость

Используется существующий кеш `tool_support` по интеграции, модели и
`runtime_revision`. Проверка в карточке агента остаётся общей проверкой
`modelSupportsTools`; отдельного сетевого probe в транзакции хода нет.

Проверочный чат возвращает дополнительные поля, также при отказе провайдера:

- `skillSupport`: `supported`, `unsupported` или `unknown`;
- `skillWarning`: локализованное RU/EN-пояснение при подключённых навыках
  и известной несовместимости; иначе пустая строка.

При `unsupported` каталог и функция не предлагаются; обычный ответ идёт
штатным путём, подключение навыка сохраняется. При `unknown` допускается
обычный запрос с функцией, как для внешних инструментов. Отказ провайдера
обрабатывается штатным отказом хода/передачей человеку; повторного запроса
с полными инструкциями нет. Агент без навыков сохраняет обычный запрос.

## Общие ограничения

| Объект | Предел |
| --- | --- |
| Навыки в снимке | 100 |
| Каталог после псевдонимизации | 64 КиБ UTF-8 |
| Инструкция до псевдонимизации | 32768 символов, как у административного API |
| Одна загруженная инструкция после псевдонимизации | 256 КиБ UTF-8 |
| Раунды с внутренними и внешними вызовами вместе | 5, затем один заключительный ответ с `tool_choice=none` |
| Операции за весь ход, включая ошибочные и повторные | 20 |
| Аргументы одной операции | 16 КиБ JSON с `ensure_ascii=true` |
| Сумма возвращаемых результатов всех операций | 512 КиБ UTF-8 |

Избыточный снимок целиком исключается из запроса, без частичного каталога.
Избыточный пакет вызовов отклоняется до исполнения с `operation limit
exceeded`; расход модели сохраняется в учёте. Результат, не помещающийся
в оставшийся объём, заменяется `operation_volume_exceeded`.
Если не помещается даже код ошибки, ход завершается штатным отказом.
Пятый раунд не даёт нового бюджета. Вызовы после заключительного запрета завершают ход
штатным отказом.

Абсолютный срок общий: новые раунды и внутренние загрузки не начинаются
после него; внешние вызовы ограничены остатком и своими 30 секундами.
Сетевой таймаут модели уменьшается до остатка перед каждой попыткой,
backoff не пересекает срок. Опоздавший ответ не доставляется, его токены
учитываются. Перед фиксацией живого ответа `ai_turn_completion` блокирует
и перечитывает диалог: ручной перехват во время сетевой части или отключение
агента отменяют ответ, сохраняя учёт. Срок повторно проверяется перед записью.

## Псевдонимизация и учёт

Каталог, загруженная инструкция, описания и схемы функций проходят одну
карту хода. UUID, если его часть распознана как персональное число, может
содержать токен: аргумент восстанавливается только в памяти перед поиском
в снимке. Описания/значения и имена полей схем маскируются; ключи аргументов
внешней операции восстанавливаются перед вызовом. Протокольные имена функций
служат непрозрачными идентификаторами маршрутизации и не меняются.

Карта восстановления не сериализуется и не сохраняется. Диагностика получает
прошедшие маскировку запросы/результаты и штатный DiagnosticRedactor; исходные
значения, инструкции до маскировки и отдельные копии аргументов не добавляются.
Каждый раунд модели проходит существующий `record_chat`, включая расход
неудачного/заключительного раунда. Внутренняя загрузка не создаёт
ToolCallRecord, события сетевого инструмента или плашки в истории.

Проверочный чат хранит только штатный учёт обращений LLM; контактов,
диалогов, сообщений, outbox и диагностики клиентского хода не создаёт.
Повторная проверка полномочий проверочного чата выполняется в короткой
tenant-транзакции: вне неё RLS скрыл бы membership от runtime-роли app.
Следующий ход получает текст сохранённого ответа и новую карту.

## Разделение ответственностей

`turn_skills` отвечает за снимок/каталог/загрузку, `operation_masking` — за
схемы функций, `tool_loop` — за общий цикл и бюджеты, `chat_execution` — за
поход к провайдеру и срок повторов, `turn_types` — за структуры плана/ответа.
`turn` остаётся сборкой этапов. Сервисы библиотеки, права, UI и транспорт
не дублируются. `conversations.ai_turn_completion` отвечает за фиксацию
результата живого хода с повторной проверкой управления и срока.
