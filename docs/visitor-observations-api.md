# Серверные наблюдения посетителя

`GET/POST /api/v1/webchat/observations/` используют действующий токен
WebSession (`Authorization: Bearer …`) и существующие лимиты публичного API.
Для этого endpoint токен принимается только в заголовке, не в URL или теле.
Срок действия проверяется штатным механизмом сессий. Токен другой сессии
не даёт доступ к её наблюдениям; организация и WebSession определяются
сервером, а не полями запроса. Токены и их хеши в ответах не выдаются.

POST принимает одно событие:

```json
{"tabId": "044cf580-d8d9-4192-9d18-e26ebc03a7ac", "sequence": 1, "kind": "heartbeat"}
```

`tabId` — ненулевой UUID отдельного документа/вкладки. Клиент создаёт новый
UUID при новой загрузке документа, сохраняет его при восстановлении из
BFCache и не делит его между вкладками. `sequence` — целое от 1 до
9223372036854775807, строго возрастает для всех видов событий этого документа.
При смене WebSession последовательность начинается заново в её контексте.
Сервер атомарно принимает только номер больше сохранённого; повтор и старое
событие возвращают `accepted: false` без обновления состояния и времени.
Порядок определяется номером, время получения — серверными часами.
Одновременно хранятся не более 64 документов одной сессии.

| kind | Изменяемое наблюдение |
|---|---|
| widget_open / widget_close | widget: open / closed |
| page_visible / page_hidden | page: visible / hidden |
| page_freeze / page_resume | page: frozen / resumed |
| page_hide / page_show | page: pagehide / pageshow |
| heartbeat / connection_lost | connection: connected / lost |

Событие меняет только свою ось. Начальное состояние каждой оси — `unknown`.
Heartbeat посылается каждые **30 секунд**. Спустя **90 секунд** после последнего
принятого heartbeat API показывает `connection: lost`; новый heartbeat
восстанавливает `connected`. Повтор старого heartbeat не продлевает связь.
Порог — техническая политика, согласованная владельцем для этой задачи.
Отдельный воркер для вычисления свежести не требуется: она вычисляется при
чтении, даже после перезапуска backend.

POST возвращает `accepted` и `observation`. GET возвращает
`heartbeatIntervalSeconds`, `heartbeatTimeoutSeconds` и `tabs`: отдельные
наблюдения текущей WebSession, без сводного вывода об уходе посетителя.
Наблюдение содержит `tabId`, `sequence`, `widget`, `page`, `connection`,
`departure`, `receivedAt`, `heartbeatAt` (null до первого heartbeat).
Без сигналов `tabs` пуст. Неверный/истёкший токен даёт 401; неверное событие
или превышение предела документов — 400; срабатывание лимита запросов — 429.

`page_show` и `page_resume` сами по себе не означают видимость вкладки.
`page_hide` фиксирует lifecycle, включая возможный BFCache, а не доказанный
уход. Скрытая/замороженная вкладка и закрытый виджет также не доказывают уход.
`departure` остаётся `unknown` при всех поддержанных сигналах. Наблюдения не
меняют диалог, не создают сообщений и не ставят операции в outbox. Ручная
почтовая отправка не зависит от наличия наблюдений. Сбор браузерных сигналов
и интерфейс реализуются отдельными задачами; здесь UI не меняется.
