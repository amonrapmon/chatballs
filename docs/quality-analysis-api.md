# Анализ качества: серверный API

Анализ независим от UI и исходно выключен. Настройки доступны OWNER/ADMIN.
Рабочее включение требует реальных критериев и шкал компании; сервер не
создаёт примерные критерии и не включает анализ автоматически при обновлении.
Обычным операторам управленческие результаты недоступны. Супервизор читает
и корректирует результаты только диалогов **текущих подконтрольных групп**;
его рабочие группы, назначение или участие сами по себе такой доступ не дают.
OWNER/ADMIN доступны все диалоги своей организации. Блокировка, смена роли
и отзыв контроля применяются при каждом обращении, включая ссылки на основания.

Все пути ниже относительно `/api/v1/organizations/{public_id}/conversations/`.

| Метод и путь | Назначение |
| --- | --- |
| GET `quality/settings/` | `enabled`, текущие `criteriaVersion` и `criteria` |
| PUT `quality/settings/` | OWNER/ADMIN: `enabled`, необязательный новый `criteria` |
| POST `{id}/quality/launch/` | OWNER/ADMIN: `operationId` UUID, необязательный `repeat` boolean |
| GET `{id}/quality/` | Все ревизии анализа разрешённого диалога |
| GET `quality/jobs/{job_id}/` | Состояние и результат одной ревизии |
| POST `quality/jobs/{job_id}/corrections/` | `expectedRevision`, `criterionCode`, `value`, `reason` |
| GET `quality/jobs/{job_id}/messages/{message_id}/` | Публичное сообщение-основание указанного результата |
| GET `quality/report/` | Источник отчётных строк со снимками шкал |

Критерий содержит `code` (уникальный slug до 64 символов), непустой
`description` и непустой список `scale` из строк или конечных чисел.
Изменение критериев создаёт новую версию и не изменяет прошлые результаты.
Тип значения имеет значение: boolean, integer и float не взаимозаменяются.
PUT без `criteria` сохраняет текущую версию. Нельзя включить анализ без критериев.

При штатном ручном или автоматическом закрытии факт CLOSED атомарно создаёт
снимок публичных клиентских, человеческих и AI сообщений и работу в outbox.
Служебные сообщения, внутренние комментарии и причины передачи исключены.
Единица анализа: диалог, UUID операции CLOSED, версия критериев, хеш истории.
Повтор той же операции возвращает первоначальную работу; `repeat=true`
с новым UUID сохраняет отдельную ревизию. Запуск без реального CLOSED даёт
HTTP 400 с `state=unavailable`, `errorCode=missing_history` и локализованным
`detail`; клиент не задаёт время или UUID завершения.

Штатный worker-events вызывает общий слой AI invocation и псевдонимизации
через явно выбранную интеграцию агента обращения. Персональные значения
восстанавливаются только после структурного разбора ответа. Карта токенов,
сырой ответ и подробности исключений провайдера не сохраняются в outbox или
результате. Технический журнал вызова хранит модель, расход и длительность.
Внешний вызов выполняется вне транзакции БД.

`state`: WAITING → RUNNING → SUCCEEDED или FAILED. `errorCode` различает
`provider_unavailable`, `invalid_result` и `analysis_interrupted`.
Недоступная/отключённая интеграция или отсутствие агента не приводят к выбору
провайдера другого агента. Неполный JSON, лишние поля, неверная шкала,
повтор/пропуск критерия, неизвестные токены или основания из другого диалога
не создают результат. Каждый вывод требует хотя бы одно основание.
Рекомендации — список строк, допустим пустой список.

Повтор worker не вызывает модель после терминального результата. Доставка
во время выполнения повторяется через outbox. Если процесс прервался и
RUNNING старше 300 секунд, повтор завершает работу `analysis_interrupted`;
новый анализ требует явной новой ревизии. Исходное решение не перезаписывается.

Выдача содержит `criteriaVersion`, полный снимок `criteria`, `revision`,
`historyRevision`, `completionEventId`, `completedAt`, состояния и время работы.
`conclusions[]` раздельно выдаёт `originalValue`, `effectiveValue`, `explanation`,
`recommendations`, серверные ссылки `evidence[]` и `evidenceAvailable`.
`corrections[]` хранит все ревизии, новое значение, автора, серверное время и
причину; `correctionRevision` применяется как `expectedRevision` следующего POST.
Несовпадение версии возвращает HTTP 409 и ничего не перезаписывает.
Причина обязательна, значение проверяется по шкале **исходной** версии.
Ссылка на основание проверяет текущие права, принадлежность и публичность
сообщения. Удалённое основание не выдаётся как действующая ссылка.
Ответы имеют `Cache-Control: private, no-store`.

`temporalFacts.state` — `available` или `missing_history`. Временные факты
вычисляют `conversation_observations` и `Metrics` отчёта поддержки, по событиям
до данного завершения. Единица — секунды, формулы ожидания, обработки,
первого/последующих человеческих и AI ответов общие с отчётом. Учитывается
граница доступности источников и начало диалога. При неполной истории основные
значения равны null, отдельно доступны наблюдаемые факты. После успеха этот
расчёт сохраняется в исходном результате; модель не поставляет временные поля.

Отчёт требует `from`, `to` (ISO 8601 с часовым поясом), `timezone` (IANA).
Необязательные `employee`, `group`, `connection`, `transport` совпадают с
контрактом отчёта поддержки. Период полуоткрытый, по времени завершения;
измерения берутся из факта CLOSED, права — из текущей области контроля.
Чужие/недоступные ID фильтров дают HTTP 404. Источник выдаёт **все ревизии**,
не усредняет разные шкалы; потребитель отчёта выбирает ревизию явно.
Новых фоновых уведомлений с результатами или клиентских сообщений анализ
не отправляет.

Физическое удаление диалога штатным сервисом удаляет его задания, снимки,
результаты и корректировки транзакционным SQL-каскадом. Отдельное удаление
результата и изменение исходных решений по-прежнему запрещены БД.

Проверки в окружении задачи (без seed, изменения аккаунтов или внешних заглушек):

```powershell
docker compose build backend-app backend-admin worker worker-events
docker compose exec -T backend-admin python manage.py check
docker compose exec -T backend-admin python manage.py makemigrations --check --dry-run
docker compose exec -T backend-admin pytest chatballs/conversations/quality chatballs/conversations/test_domain_event_sources.py chatballs/conversations/test_support_timeline.py chatballs/conversations/test_support_report.py chatballs/conversations/test_lifecycle.py chatballs/i18n/tests.py --reuse-db -q
docker compose exec -T backend-admin python manage.py verify_quality_runtime
```

После изменения миграций перед этими проверками окружение запускается через
Skaro `start_environment`, выполняющий сборку и штатный init. Успешный контракт
ответа и ошибки внешнего вызова в unit-тестах проверяются на границе `run_chat`;
реальный Demo-провайдер отдельно проверяет отклонение неподходящего JSON.
`verify_quality_runtime` читает уже существующие данные в READ ONLY транзакции,
не запускает AI и не включает анализ.
