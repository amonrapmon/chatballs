# Интерфейс шаблонов ответов

Источник интерфейса — `design/baseline/platform-expansion/Настройки · новые разделы.dc.html`
(N3–N9), `Чат · состояния.dc.html` (T1–T3), вложенный `Редактор ответа.dc.html` и
блок «Разрешения» кадров E2–E4 файла `Сотрудники и агенты.dc.html`.
Серверная часть описана в `docs/reply-template-libraries.md`.

## Библиотека

Библиотека открывается в разделе настроек «Шаблоны ответов». У сотрудника без
доступа к настройкам она открывается из меню пользователя отдельной страницей
`/reply-templates`: сайдбар без навигации, как на «Профиле».

Список считает сервер: область, поиск по названию и тексту, одна категория,
все выбранные теги, страница. Счётчики вкладок — полное число шаблонов области.
Право управления общей областью читается из `/templates/permissions/`; до
ответа сервера интерфейс не показывает ни управление, ни «только
использование». Личной областью сотрудник управляет сам, чужие личные шаблоны
сервер не выдаёт. Область существующего шаблона не меняется — так устроен
контракт API; после сохранения открывается вкладка области шаблона.

Пустой результат фильтра называет запрос и категорию и предлагает «Сбросить»;
он не выдаётся за пустую библиотеку.

## Категории и теги

Страница показывает справочники той области, которой сотрудник управляет: у
сотрудника без разрешения это всегда личная область. Число шаблонов считается
по всей доступной выдаче, а не по странице. Удаление категории или тега
оставляет шаблоны в библиотеке; связи очищает сервер.

## Окно шаблона

Окно читает `/templates/variables/`, показывает переменные метками с подписью
каталога и хранит в тексте исходные маркеры. «Вставить переменную» ставит
маркер в позицию курсора. Повтор названия показывается у поля названия,
неизвестная переменная — у текста, со списком доступных; подвал считает ошибки.
Текст существующего шаблона не отправляется, пока его не меняли: удалённое
дополнительное поле не мешает переименовать шаблон.

## Вставка в сообщение

Кнопка «Шаблоны» и «/» в начале поля открывают одно меню над редактором:
поиск по названию и тексту, области «Все · Личные · Общие», следующие страницы
подгружаются при прокрутке. Стрелки выбирают, Enter вставляет, Esc закрывает
выбор и убирает набранное «/…».

Выбранный шаблон подставляет сервер через `/templates/{id}/render/` для
текущего диалога; значения контакта, сотрудника и организации клиент не
передаёт. Ответ, пришедший после смены диалога, не применяется.

Меню и проверка действуют для обеих аудиторий редактора — ответа клиенту и
внутреннего комментария. Поле сообщения — редактор с метками переменных;
метка у текста из ИИ-черновика выравнивается по нему так же, как раньше по
`textarea`. При смене диалога набранный текст очищается: подставленные
значения относятся к своему диалогу.

Вставленный текст редактируется. Пока в тексте есть маркер известной
переменной, он показан красной меткой, под редактором — что заменить, кнопка и
Enter не отправляют. Та же проверка стоит на сервере: ответ `unfilledKeys`
учитывается, пока маркер остаётся в тексте.

## Разрешение в карточке сотрудника

В правой колонке карточки сотрудника с ролью «Сотрудник» есть блок
«Разрешения» с переключателем «Управление общими шаблонами». Он читает и
меняет право через `/templates/permissions/{membershipId}/`; идентификатор
участия приходит в ответе API сотрудника полем `membershipId`. Владелец и
администратор управляют общими шаблонами по роли, поэтому у них блока нет.
При ошибке переключатель возвращается в прежнее положение, причина
показывается в блоке. Роль и доступ к настройкам право не меняет.

## Отклонения от макета

Согласованы владельцем 11.10.2026:

- Колонка «Изменён» показывает только дату: API шаблонов не возвращает автора
  изменения.
- Фильтры «Категория» и «Теги» — общий `FilterDropdown` приложения: подпись
  внутри кнопки, а не перед ней.

Прочее:

- В ошибке неизвестной переменной подписи доступных переменных выводятся как в
  каталоге сервера, без перевода в нижний регистр: иначе искажаются подписи
  вроде «Email клиента» и «ID клиента».
- Событие выдачи разрешения не попадает в блок «Аудит» карточки: он показывает
  события учётной записи, а право записывается на участие в организации.

```powershell
docker compose exec -T frontend npm run build
docker compose exec -T frontend npm run test -- src/features/conversations/templateVariables.test.ts src/auth/access.test.ts src/router.test.ts
docker compose exec -T backend-admin pytest chatballs/conversations/test_template_permissions.py --reuse-db
```

Браузерная проверка идёт со штатным backend окружения задачи и существующими
демо-записями из `identity/demo_seed/data/ru/organization.json`; seed и
изменение учётных данных не нужны.
