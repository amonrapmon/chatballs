# Данные передачи диалога

Справочник организации доступен по tenant-маршруту:
`/api/v1/organizations/{organization_public_id}/conversations/transfer-reasons/`.
Все операции требуют активного участия OWNER или ADMIN в этой организации.

- `GET` возвращает `{items: [{id, code, name, isActive}], page, pageSize, total, pageCount}`,
  включая отключённые причины. Параметры страниц — штатные `page` и `pageSize`.
- `POST` принимает `{code, name, isActive?}` и возвращает `{reason: ...}` с HTTP 201.
- `GET /{id}/` возвращает `{reason: ...}`.
- `PATCH /{id}/` принимает изменяемые поля и возвращает `{reason: ...}`.
- `DELETE /{id}/` отключает причину и возвращает HTTP 204. Физического удаления нет.

Код — до 64 латинских букв, цифр, дефисов и подчёркиваний; уникален внутри
организации. Название — непустая строка до 120 символов. Новая причина активна,
если `isActive` не задано. Коды разных организаций независимы.

`transfer_services.record_transfer` — внутренний сервис записи журнала для
последующей атомарной операции назначения. Он принимает tenant-контекст,
диалог, ID прежнего/нового ответственного, ID причины, внутренний комментарий
и UUID операции. Отсутствие прежнего ответственного передаётся как `None`.
Инициатор берётся из контекста, время устанавливает сервер. Код и название
активной причины копируются под блокировкой строки. UUID уникален в организации;
повторная вставка отвергается ограничением БД. Обработка идемпотентного повтора
относится к операции назначения.

Сервис проверяет право на диалог, организацию участников и активность получателя.
Он сам не меняет ответственного: вызывающая операция должна сохранять реальную
смену и журнал в одной транзакции. Политика рабочих статусов, конкурентная версия,
уведомление и защищённая выдача журнала реализуются отдельными задачами этапа.

Журнал хранится отдельно от `Message`: причина и комментарий не добавляются
в клиентскую историю, контекст AI, уведомления или обычный payload диалога.
Нет публичного HTTP-метода записи или выдачи журнала. Существующие назначения
миграция не превращает в записи передачи. Обе новые таблицы защищены RLS;
связи с диалогом, причиной и пользователями дополнительно проверяют триггеры БД.
