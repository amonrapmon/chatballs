# Данные передачи диалога

Справочник организации доступен по tenant-маршруту:
`/api/v1/organizations/{organization_public_id}/conversations/transfer-reasons/`.
Все операции требуют активного участия OWNER или ADMIN в этой организации.

- `GET` возвращает `{items: [{id, code, name, isActive, usageCount, previousName, renamedAt}], page, pageSize, total, pageCount}`,
  включая отключённые причины. Параметры страниц — штатные `page` и `pageSize`.
- `POST` принимает `{name, code?, isActive?}` и возвращает `{reason: ...}` с HTTP 201.
- `GET /{id}/` возвращает `{reason: ...}`.
- `PATCH /{id}/` принимает изменяемые поля и возвращает `{reason: ...}`.
- `DELETE /{id}/` отключает причину и возвращает HTTP 204. Физического удаления нет.

Код — до 64 латинских букв, цифр, дефисов и подчёркиваний; уникален внутри
организации. Название — непустая строка до 120 символов. Новая причина активна,
если `isActive` не задано. Коды разных организаций независимы.

Если код не передан, сервер создаёт технический UUID-код. Названия уникальны
для новых записей и изменений в организации без учёта регистра; краевые
пробелы обрезаются. Уже существовавшие записи миграция не переименовывает.
`usageCount` — число передач с этой причиной в организации.
`previousName` и `renamedAt` описывают последнее фактическое переименование;
до первого переименования они равны пустой строке и `null`.
Защищённая история дополнительно возвращает `initiatedBy`,
`previousOperator`, `newOperator` с id/именем и текущие
`reason.isActive`/`reason.currentName`. Снимок названия и код причины сохраняются.

## Настройки назначения

`GET /conversations/assignment-policy/` возвращает `{allowedStatuses: {...}}`.
`PUT` того же tenant-маршрута принимает полный объект:
`{READY: true, BUSY: true, BREAK: true, UNAVAILABLE: true}`.
Все четыре значения обязательны и должны быть логическими; лишние ключи
отклоняются. Настройки доступны только OWNER/ADMIN. Начальная политика,
согласованная владельцем 10.10.2026, разрешает все четыре рабочих статуса.
Миграция сохраняет её для существующих организаций без настройки; уже изменённые
политики не перезаписывает. Для новой организации БД атомарно создаёт запись
с четырьмя разрешениями. Дальнейшее изменение — через административный API.
При отсутствии записи (например, после её удаления) `allowedStatuses` равен
`null`, назначение отклоняется; скрытой подстановки при чтении нет.
Политика применяется и к прежнему назначению без причины. Техническое
присутствие не влияет на решение сервера.

`GET /conversations/directory/` сохраняет поиск `q`, ограничение и текущую
область видимости нагрузки. Поля сотрудника раздельны: `online`, `lastSeenAt`,
`workStatus {status, version, changedAt}`, `openDialogs`, `assignmentAllowed`.
Верхний уровень содержит `assignmentAllowedStatuses`; чужие, заблокированные
и глобально неактивные сотрудники не выдаются. Значение `assignmentAllowed`
информационное: сервер повторно проверяет получателя при операции.

## Передача через существующее назначение

`POST /conversations/{conversationId}/assignee/` принимает:

```json
{
  "userId": 15,
  "reasonId": 2,
  "comment": "Внутренний комментарий",
  "expectedVersion": 0,
  "operationId": "f17b7dad-5a64-487d-bc41-ec43092264ec"
}
```

Все пять полей обязательны для передачи с причиной. `operationId` — UUID;
`expectedVersion` — неотрицательное целое, полученное из `assignmentVersion`
обычного payload диалога. Получатель и причина должны принадлежать организации,
получатель должен быть активен, неблокирован и разрешён политикой; причина —
активна. Текущий отправитель должен иметь право назначения для этого диалога.
Передача самому текущему ответственному отклоняется. Закрытый диалог не меняется.

Успех возвращает `{transfer: {id, conversationId, operationId, assignmentVersion,
initiatedById, previousOperatorId, newOperatorId, occurredAt, reason: {id, code,
name}, comment}}`. Сервер сохраняет смену ответственного, снимок причины и
комментарий, доменный факт `TRANSFERRED` (первое назначение — `ASSIGNED`), адресное
уведомление и его outbox в одной транзакции. Режим AI не переключается.
Уведомление имеет отдельный ключ операции, сохраняет код текста и ссылку на
диалог; внутренних подробностей в нём нет. Контекст доставки системный, поэтому
отзыв доступа отправителя не отменяет адресное уведомление получателя.
Штатный обработчик повторно проверяет доступ получателя перед доставкой;
его повтор не выполняет назначение. Сбой фоновой доставки не откатывает операцию.

При конкуренции сервер возвращает HTTP 409 с `assignmentVersion` и
`assignedOperatorId` актуального назначения. Версию увеличивает триггер БД при
любой смене ответственного, включая claim, release, снятие очередью и прежний API.
Повтор UUID тем же отправителем в том же диалоге возвращает первоначальный снимок,
даже после следующей передачи или отключения причины. Текущее право на диалог
проверяется заново. Коллизия UUID с другим диалогом или отправителем получает
409 без содержимого чужой операции.

Для совместимости сохраняется прежний запрос `{userId}` без причины и снятие
`{userId: null}`. Они используют тот же сервис; назначение проверяет политику,
любая реальная смена увеличивает версию. Этот прежний формат не является
передачей с причиной и не создаёт запись нового журнала.
Для прежнего назначения можно передать UUID в заголовке `Idempotency-Key`;
повтор сохраняет актуальное назначение и не дублирует доменный факт.
Передача с причиной отклоняет UUID, уже занятый другой доменной операцией.

`GET /conversations/{conversationId}/transfer-options/` выдаёт пагинированный
список активных причин для сотрудника с действующим правом назначения.

## Защищённый журнал

`GET /conversations/{conversationId}/transfers/` возвращает
`{items: [transfer], page, pageSize, total, pageCount}`. Параметры — `page` и
`pageSize`, порядок — от новых записей к старым, с ID как вторым ключом.
`GET /conversations/{conversationId}/transfers/{transferId}/` выдаёт
`{transfer: ...}`. Оба запроса требуют текущего доступа к диалогу и соответствия
организации. Знание ID, прежнее назначение или участие не заменяет действующих
прав. Отсутствующий и недоступный объект получает одинаковый HTTP 404.
Код и название причины берутся из записи передачи, поэтому переименование и
отключение справочника не изменяет историю.

Защищённое представление дополнительно содержит имена и `avatarUrl`
отправителя, прежнего и нового ответственного, `conversation.contactName`
и `conversation.provider` для карточки получателя. Эти поля не добавляются
в неизменяемый ответ POST или идемпотентного повтора. Уведомление и системное
сообщение содержат только `transferId`; внутренние детали интерфейс читает
по этому ID из защищённой истории с повторной проверкой доступа.

Журнал хранится отдельно от `Message`: причина и комментарий не добавляются
в клиентскую историю, контекст AI, уведомления или обычный payload диалога.
Внутренний `transfer_services.record_transfer` остаётся writer для атомарного
сервиса назначения и не имеет публичного метода записи. Таблицы причин,
журнала и политики защищены RLS; связи журнала дополнительно проверяют
триггеры БД. Миграция вводит версию существующих назначений как 0 и не
восстанавливает старые передачи. UI передачи и настроек в эту задачу не входит.
## Общий защищённый журнал

`GET /api/v1/organizations/{organization_public_id}/conversations/{id}/activity-history/`
возвращает общий журнал для P6. Параметр `kind` принимает `all`, `transfers`,
`participants`; `page` и `pageSize` следуют штатному контракту пагинации.
Сортировка по времени, типу и идентификатору выполняется на сервере до
пагинации. В память загружаются только записи текущей страницы.

Каждое подключение и завершение участия — отдельное событие с соответствующей
причиной, инициатором и временем. Передача сохраняет снимок названия причины,
комментарий и сведения о текущем переименовании/отключении. Чтение требует
текущего доступа к диалогу; чужая организация и утраченный доступ дают 404.
Данные журнала не добавляются в клиентскую переписку, AI-контекст или realtime.

Событие взятия из очереди выводится только для штатного `operator_took`,
в котором сервис сохранил подтверждённый признак `fromQueue` и автора.
Старые события без этого признака не восстанавливаются по догадке.
