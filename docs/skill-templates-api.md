# Безопасные шаблоны навыков

T-159, SPEC-0035 R-11–16, R-30–34. Это серверный контракт для редактора и
будущего runtime. Подключение к циклу модели, доставка снимка в Message и
продуктовый renderer выполняются соответствующими задачами этапа.

## Конфигурация и права

В общей `configuration.templates` каждый объект имеет ровно поля:

```json
{
  "id": "b1787429-4258-4866-8e6b-e350e0b1e55b",
  "name": "Карточка заказа",
  "purpose": "Когда нужен состав заказа",
  "schema": {
    "type": "object",
    "properties": {
      "order_no": {"type": "string", "required": true, "description": "Номер из источника"}
    }
  },
  "html": "<p>Заказ {{ order_no }}</p>",
  "css": "p {color: #262626}",
  "text": "Заказ {{ order_no }}",
  "examples": [{"order_no": "4512"}]
}
```

UUID стабилен при правках; уникален внутри навыка. Пространство идентификаторов
принадлежит навыку, поэтому runtime обязан выбирать `(skillId, templateId)` из
загруженного подключённого навыка, а не искать templateId глобально. Полный GET
возвращает исходники и примеры; список — только id/name/purpose и templateCount.
Шаблоны хранятся в JSON-колонке Skill: у них те же FORCE RLS, владелец и срок
жизни; отдельного публичного API шаблонов нет. POST/PUT сохраняет весь набор
атомарно с expectedRevision и requestId, как описано в API библиотеки.
Ошибка откатывает все части и не повышает ревизию.

Схема имеет корень object. Узел: type, optional boolean required (по умолчанию
false), optional description; object дополнительно требует properties, list —
items (один узел типа). Типы: string/number/boolean/object/list. Имена полей:
ASCII-буква и до 63 букв/цифр/подчёркиваний. Неизвестные ключи запрещены.
Число конечно, модуль не более 10^15; bool не является number. Обязательные
значения нельзя пропускать/передавать null, обязательная строка непустая.
Необязательный объект/null не требует присутствия вложенных полей.
Дубликаты ключей JSON отвергаются до создания словаря.

## Ограниченный язык

Поддерживаются только `{{ field }}`, `{{ object.field }}`,
`{{#each list}}…{{/each}}`, `{{#if field}}…{{/if}}`. Контекст each — элемент;
доступ к родителю/глобальным объектам отсутствует. Для скалярного элемента
списка используется `{{ this }}`. Объекты и списки напрямую не интерполируются.
if проверяет наличие: missing/null/пустая строка скрывают блок; 0/false
остаются значениями и показывают его. Отсутствующая необязательная подстановка
пустая; числа форматирует серверный `i18n.formatting.fmt` по языку организации,
boolean выводится true/false. Это форматирование типа, не вызов функции в языке.
Выражения, raw/triple braces, include, функции и доступ к коду не поддерживаются.
HTML-блоки сохраняют структуру и находятся между тегами; подстановка в атрибут
допустима только внутри кавычек. Ветви проверяются независимо от примеров.
HTML-подстановки экранируются для текста и кавычечных атрибутов; после рендера
снова выполняются разбор и очистка. В CSS подстановок нет.

## Проверка, предпросмотр и runtime

База: `/api/v1/organizations/{organizationPublicId}/skills/`.
Все маршруты требуют штатную session/CSRF и активного OWNER/ADMIN.

| Метод и путь | Тело/результат |
| --- | --- |
| POST `validate/` | `{configuration}` → `{valid:true}` |
| POST `preview/` | `{configuration,templateId,data}` → безопасный результат |
| POST `{skillId}/validate/`, `{skillId}/preview/` | То же, с проверкой принадлежности существующего навыка |
| GET `bases/orders/` | `{basisId:"orders-v1",configuration}` — локальная редактируемая основа |

Проверка сохраняемости не рендерит examples. Пример может быть временно
незаполненным: это не делает исходники ошибочными. Перед предпросмотром отдельно
проверяются переданные data. Ни один из этих маршрутов не меняет библиотеку,
аудит, ревизии, подключения, сообщения и не обращается к внешним инструментам.

Единственный обработчик — `skill_templates.engine.render_template(template,
data, language=customer_language(organization), origin="data")`. Предпросмотр
вызывает его с origin="example"; сохранение использует его же compile_template.
Будущий runtime проверяет доступность навыка и восстанавливает известные
псевдонимы **до** вызова обработчика. После него подстановка/восстановление
запрещены. Обработчик не исполняет инструменты и не отправляет сообщения.

Результат:

```json
{
  "text": "...",
  "contentHtml": "<p>...</p>",
  "presentation": {
    "formatVersion": 1,
    "css": "...",
    "isolation": "sandboxed-iframe",
    "sandbox": "",
    "srcDoc": "<!doctype html>..."
  }
}
```

contentHtml и css не предназначены для вставки в DOM оболочки. Потребитель
отображает **srcDoc** в `<iframe sandbox="" referrerpolicy="no-referrer">`, без
allow-scripts/allow-same-origin/allow-top-navigation/allow-forms. Размер frame
ограничивается пузырём сообщения; дополнительные разрешения не добавляются.
srcDoc содержит CSP `default-src 'none'; style-src 'unsafe-inline'; base-uri
'none'; form-action 'none'`, meta referrer и базовый box-sizing. Это отдельный
документ с opaque origin; CSS физически не достигает соседей/оболочки. Пустой
sandbox также блокирует открытие ссылок; расширять его ради навигации нельзя.
Для ссылки сохранены только http/https, rel=noopener noreferrer,
referrerpolicy=no-referrer; небезопасные URI, credentials, относительные адреса,
управляющие символы и обратные слеши запрещены.

HTML5 разбирает html5lib в strict-режиме, окончательно очищает nh3. Положительный
список включает простую текстовую/табличную разметку и минимальные svg/path/
circle/line/polyline для статической иконки часов. Нет style/id, событий, форм,
iframe, изображений, мультимедиа, foreignObject/use, анимации или ресурсов.
Разрешены class/title, href для a и ограниченные статические SVG-атрибуты.
Комментарии запрещены. Пользовательский SVG не имеет URL/ссылок/скриптов.

CSS разбирает tinycss2: только qualified rules и положительный список свойств
типографики, размеров, границ, отступов, flex/grid и счётчиков. Точные списки —
`css_policy.py`. Значения — числа 0…2000, px/em/rem/fr/%, идентификаторы/цвета,
rgb/rgba/minmax/repeat/counter. Строки только в content, без `<`. Селекторы:
теги/классы, группы и комбинаторы, псевдоэлементы и ограниченные has/nth-child
для счётчика строк основы. Нет at-rules, import, url, var, expression,
position/z-index, внешних шрифтов, viewport-единиц, отрицательных размеров,
important. Дополнительно отвергается незавершённый CSS, который парсер мог бы
восстановить. Замены regex не используются как механизм очистки CSS/изоляции.

## Диагностика и конечные лимиты

400: `{code:"invalid_template",origin:"configuration"|"example"|"data",detail,
errors:[{code,detail,origin,tab,path,line?,column?}]}`. Вкладки:
schema/html/css/text/example. Строка и колонка с 1; пути: `templates[0]`,
`items[1].price`. Пояснения из RU/EN-каталогов, исходный ввод не отражается.
Коды: limit/invalid_value/invalid_schema/required/type/unknown_field/syntax/
html_policy/css_policy. Для base-полей остаётся контракт SkillError библиотеки.
Некорректный пример origin=example отличается от дефекта конфигурации.

| Ограничение | Значение |
| --- | --- |
| HTTP-тело до JSON/CSRF | 160000 байт, превышение 413 |
| Полная конфигурация (UTF-8 JSON) | 150000 байт |
| Инструкция | 32768 символов и общий бюджет конфигурации |
| Каждый HTML/CSS/text | 24000 байт UTF-8 |
| Схема | 16000 байт, 128 узлов, глубина 8 |
| name/purpose шаблона | 60/500 байт UTF-8 |
| Описание поля | 500 символов |
| Шаблоны / примеры на шаблон | 8 / 8 |
| Все примеры шаблона / runtime data | 48000 байт JSON |
| Строка данных | 8000 символов |
| Элементы каждого списка | 100 |
| Предварительный обход JSON | 4096 узлов, глубина 24 |
| Вложенность блоков | 7 блоков внутри корня |
| Операции рендера | 20000 на представление; элементы each тоже учитываются |
| CSS | 128 правил, 512 деклараций, глубина функций 4 |
| Результат | 128000 байт на представление и суммарно text+HTML+CSS+srcDoc |

## Основа и проверки

GET основы не устанавливает её. Выбор заполняет локальный набор формы;
явное сохранение отправляет обычный POST библиотеки с requestId. Повтор
одного запроса возвращает ту же копию; отдельные запросы могут намеренно
создавать разные навыки. Смена языка организации/обновление образца не меняют
сохранённые копии. Нет seed, собственной таблицы заказов, интеграций или
автоподключения к агентам. Названия, подписи и примеры выбираются по языку
организации; инструкция для модели остаётся системной английской инструкцией.

Карточка содержит order_no, items[{title,qty,price,sum}], total; статус —
order_no/status и необязательный eta. Данные примеров — только образцы редактора.
Суммы в них явно заданы по baseline; обработчик ничего не пересчитывает.
Счётчик позиций — CSS counter, формы подписи выбираются tn, разряды — fmt.
RUB разрешён инструкцией только при подтверждении валюты источником. Обработчик
не может проверять достоверность коммерческих фактов: это обязанность
инструмента и runtime. При иной/неизвестной валюте инструкция требует достоверный
текст или передачу человеку. Изменение/отмена заказов запрещены; внешняя система
сама проверяет принадлежность заказа. Никаких автоматических ответов примерами.

Целевые тесты: test_skill_template_language/security/limits,
test_skills_templates_api, затронутые test_skills_api/access/concurrency/rls и
i18n CatalogTests. Запуск только с `--reuse-db` через штатный backend-admin;
полный набор проекта не запускается. Миграцию применяет штатный init при
`start_environment`; применимость проверяет `makemigrations --check --dry-run`.
