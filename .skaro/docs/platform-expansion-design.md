# Дизайн расширения платформы

Владелец предоставил архив «Дизайн системы из кода.zip» 10.10.2026 для подготовки фронтенд-работ. Все 16 файлов размещены без изменения содержимого в `design/baseline/platform-expansion/`; каждый сверён с архивом по SHA-256.

Основная инструкция для coding-агента: [INTEGRATION.md](../../design/baseline/platform-expansion/INTEGRATION.md). Она содержит конкретные HTML и кадры для каждой задачи, порядок чтения, ограничения просмотра и согласованные исключения. Оригинальный [README дизайнера](../../design/baseline/platform-expansion/README.md) сохранён; его предложения не меняют архитектуру автоматически.

Дизайн относится к 15 существующим задачам: T-051, T-057, T-060, T-064, T-071, T-076, T-087, T-093, T-105, T-113, T-132, T-141, T-142, T-144, T-151. Это текущая группировка этапов M08–M19; исходные 26 интерфейсных частей старого плана не создаются заново. Границы, критерии, зависимости и статусы задач не изменяются этим документом.

Согласованное решение владельца о сохранении отдельной роли SUPERVISOR закреплено в разделе исключений INTEGRATION.md. Остальные отклонения от макетов требуют отдельного решения. Найденные расхождения статистики и API отмечены там же; зависимые элементы нельзя объявлять готовыми только на основании наличия HTML.

Проверен браузерный рендер шести основных холстов со вложенными компонентами, светлой/тёмной темами и изображениями. Проверка относится только к предоставленным дизайн-референсам; реализация приложения и её штатный backend здесь не проверялись и не менялись.

Наличие baseline снимает ожидание дизайна показанных состояний, но не отменяет готовность серверных зависимостей и разрешение отмеченных противоречий. В рабочем checkout задачи должны быть доступны сами файлы baseline и INTEGRATION.md; уже созданный worktree не получает незакоммиченные файлы основной копии автоматически.

Общая замена логотипа и добавление ссылки «Помощь» в оболочку показаны в архиве, но не входят в цели перечисленных 15 задач. Они не добавляются в эти задачи молча; инструкции по их отдельной реализации находятся в INTEGRATION.md.
